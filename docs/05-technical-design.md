# 05 技术设计

> 涵盖技术架构、性能、设置、异常处理、跨平台、可访问性与安全。  
> [返回文档导航](requirements.md)

## 9. 技术架构

### 9.1 模块划分

| 模块 | 职责 |
| --- | --- |
| `MindTreeView` | 注册自定义视图、管理生命周期和状态提示。 |
| `TreeCanvas` | 渲染、布局、选择、缩放、拖拽和可访问性。 |
| `TreeCommandService` | 封装新增、移动、删除、标记等原子命令及撤销/重做。 |
| `DocumentRepository` | 解析、校验、序列化和原子保存 `.mtn.md`。 |
| `MindTreeMigrationFactory` | 按 `schemaVersion` 登记并逐级执行文件结构迁移，向当前领域模型提供唯一兼容入口。 |
| `OutlineRenderer` | 根据树数据单向生成 Markdown 无序列表。 |
| `FileIndexRepository` | 建立、持久化和修复资源索引。 |
| `ResourceService` | 创建、关联、打开、移动文件与处理标题同步。 |
| `ClipboardService` | 写入和读取自有 JSON、Markdown、PNG。 |
| `ExportService` | 生成 PNG 和 Markdown 导出结果。 |
| `SettingsService` | 设置读写和默认值。 |

核心树操作必须与 UI 框架解耦，并通过纯数据单元测试验证。所有文件变更统一经过 `ResourceService`，避免菜单、命令和拖拽各自实现一套规则。

### 9.2 状态流

```text
.mtn.md ──解析/校验──> 领域模型 ──命令──> 新领域模型
   ▲                       │                  │
   │                       ├──> 画布渲染      ├──> 撤销栈
   │                       └──> 资源解析      └──> 延迟保存
   └── 大纲 + 压缩数据区 <──── 序列化 <────────┘
```

领域模型是视图会话中的唯一状态源。组件不得直接修改模型；所有修改都通过命令产生，以保证撤销、保存和测试行为一致。

持久化边界统一由 `DocumentRepository` 负责：文件头写顶层 `schemaVersion` 和六项文档设置，仅在导图已获得跨文件资源身份时写 `documentId`；正文写 Markdown 大纲、AI 忽略提示和 gzip + Base64 压缩 JSON 数据区；`ClipboardService` 的 JSON 是独立的临时交换格式。关联文件状态在文件事件、文档重新加载和序列化之前经过同一校正层：规范路径始终覆盖 `pathHint`，规范文件名只覆盖启用双向标题同步的节点，避免 Obsidian 链接改写载入旧压缩快照后恢复旧标题。

### 9.3 渲染与性能策略

- 布局计算和渲染分离；节点尺寸变化时只使相关分支布局失效。
- 画布导航拆成平移层与内容缩放层：外层只执行屏幕空间平移，内层优先使用会触发布局和文字重新栅格化的 CSS `zoom`。不得在长期合成的世界层上持续使用 `transform: scale()` 拉伸节点文字；仅为不支持 CSS `zoom` 的旧 WebView 保留回退。
- 根节点、一级节点、二级及更深节点的字号、最小高度和行高由深度映射函数统一决定；深度二及以后固定返回同一档参数。节点不设固定最小宽度，总宽度由标题测量结果和尾部元素实际宽度共同决定。
- 视觉配色由一级分支决定：根节点使用主题纯色，根节点的 `childIds` 按当前文档顺序依次取得十二个色槽，第十三个分支开始循环；每个一级分支的全部后代节点和连接线继承该色槽。调整一级节点顺序会同步改变色槽；DOM 与 SVG 导出共用相同的分支槽表。所有节点和画布背景均禁止使用渐变。
- 节点先按标题估算宽度，短标题自动收缩，超过全局换行宽度后增加文本行和节点高度。同级对齐按每层最大尺寸确定共用列、行或半径；紧凑布局沿父子连接按实际节点尺寸推进，并按角度扇区留出安全半径。画布与 PNG 导出共用尺寸、换行和布局函数。
- 纵向布局以完整子树为边界递归计算：兄弟子树之间始终保留统一最小间距，再将父节点放在子树组的垂直中心。拖拽改变父子关系后必须全量重算，任何深度的节点矩形都不得重叠。
- 均衡布局按一级子树高度贪心分配左右两侧；树形布局递归计算子树宽度；放射布局按叶子权重划分角度，并根据同层节点对角线尺寸动态扩大半径。
- 连线路径与节点排布分离：布局只输出节点矩形，路径层再按布局方向选择边缘锚点，并生成贝塞尔、直线或直角路径；虚线仅由渲染样式控制。
- 大导图使用视口裁剪，仅渲染可见节点及缓冲区。
- 搜索、索引重建、PNG 导出、大纲生成和 JSON 压缩不得长时间阻塞主线程；必要时分片或使用 Worker。
- 打开时优先显示结构，再异步补齐缩略图和失效引用状态。
- 图像缩略图设置尺寸和数量上限，离开视口后释放对象 URL。

性能验收基线（普通近三年桌面设备）：

- 1,000 个纯文本节点的导图在 2 秒内完成首次可交互渲染。
- 500 个可见节点下，普通平移和缩放保持可感知流畅，交互期间不执行同步全库扫描。
- 10,000 个文件的仓库完成首次索引后，单次文件事件使用增量更新。
- 连续编辑不得每次按键写盘。

### 9.4 版本迁移约束

- 当前引入迁移机制前的无版本号文件定义为 v1，也是项目允许读取的最早兼容版本；当前写出格式为 v2。v1→v2 只补充显式版本标记。
- schema v2 以 `.mtn.md` 扩展名、有效 `schemaVersion` 和机器数据区识别导图，`documentId` 是可选链接身份；这一规范调整不提升版本。今后只有影响导图识别、机器数据区定位或核心载荷解码的不兼容结构修改才提升 `schemaVersion`，并在统一 `MindTreeMigrationFactory` 中登记从版本 N 到 N+1 的纯数据迁移。新增可缺省的树设置不提升版本、不进入工厂；视图、领域操作和序列化代码不得各自添加旧格式判断。
- 工厂严格按整数版本逐级迁移；版本低于最早兼容版本、版本高于当前版本、缺少中间迁移或迁移结果校验失败时，只报告错误，不覆盖原文件。
- 迁移在内存副本中完成。成功解析后将视图标记为待保存，由现有原子保存流程把文档、大纲与文件头统一写成当前版本。
- 全局默认布局、主题、连线样式、节点形状与文件收集策略只传给文档设置规范化层，用于缺失属性回填；迁移工厂不读取全局界面设置。
- 任意新文档属性在打开文件时缺失，统一由文档设置规范化层使用对应全局默认值（无全局项时使用代码默认值）补齐并标记待保存；业务视图不得自行维护缺失字段分支。

## 10. 设置设计

设置分为文档设置和插件全局设置。文档设置包含“布局模式”“主题”“连线样式”“节点形状”“文件收集策略”和“递归扫描子目录”，从视图左上角圆形菜单进入，并分别保存为该 `.mtn.md` 的顶层 `layoutMode`、`theme`、`connectionStyle`、`nodeShape`、`collectionMode`、`recursiveScan` YAML 属性。全局“默认布局”“默认配色主题”“默认连线样式”“默认节点形状”和“默认文件收集策略”只在新建导图时复制到文档，也作为旧文件缺失相应属性时的回填值；其余设置仍放在“基础设置 / 思维导图 / 主题笔记”三个全局设置页中。

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 模板文件夹 | 空 | “从模板添加笔记”的递归搜索范围，只读取 Markdown 模板。 |
| 新笔记目录 | 当前导图目录 | 也可选择 Obsidian 默认附件/笔记目录策略。 |
| 新笔记默认填充内容 | 空 | 普通新笔记的初始 Markdown 正文；不自动生成一级标题，也不影响模板副本。 |
| 文件收集策略 | 每次询问 | 当前树可选关闭、每次询问、添加到一级末尾或添加到“收集”节点，并写入顶层 `collectionMode`。 |
| 递归扫描子目录 | 关闭 | 避免首次打开产生大量候选。 |
| 扫描忽略规则 | 隐藏目录与插件目录 | 支持路径前缀和扩展名。 |
| 布局模式 | 均衡 | 可选均衡、向右、向左、树形和放射；左上角菜单与命令面板同步切换当前树。 |
| 默认布局 | 均衡 | 只决定新建导图的初始 `layoutMode`，不覆盖已有导图。 |
| 默认文件收集策略 | 每次询问 | 位于全局“思维导图”页，只决定新建导图的初始 `collectionMode`，也用于回填旧文件的缺失属性。 |
| 默认配色主题 | 活力 | 十套内置主题均提供浅色/深色变量；只决定新建导图的初始 `theme`。 |
| 连线样式 | 跟随主题 | 当前树可跟随主题或强制平滑/直角的实线与虚线或直线，写入顶层 `connectionStyle`；所有连线固定为 `1px`，主题继续定义端点、透明度和阴影。 |
| 默认连线样式 | 跟随主题 | 位于全局“思维导图”页，只决定新建导图的初始 `connectionStyle`，也用于回填缺失属性。 |
| 节点形状 | 圆角 | 当前树的形状，可选圆角、方角和无边框；圆角及无边框的可见非叶节点使用 `2px` 圆角，方角使用 `0px`。历史 `capsule`、`sketch` 值按普通无效设置回退为圆角，并写入顶层 `nodeShape`。 |
| 默认节点形状 | 圆角 | 只决定新建导图的初始 `nodeShape`，不覆盖已有导图。 |
| 节点对齐 | 同级节点对齐 | 全局切换为同级共用列/行/半径，或按父节点尺寸就近放置的紧凑布局。 |
| 文件名同步 | 所有新文件关联默认开启 | 可对当前树关闭新关联的默认值，也可在节点菜单逐项取消或恢复。 |
| 非 Markdown 文件标识分隔符 | `@` | 可选 `@` 或 `%`，仅用于新关联文件的 5 位大小写字母数字 ID；历史文件不自动改名。 |
| 关联文件打开位置 | 新标签页 | 可切换为右侧竖向拆分。 |
| Ctrl/Cmd+E 新文件打开位置 | 右侧拆分 | 可切换为新标签页、当前标签页或新窗口。 |
| 自动保存延迟 | 500 ms | 限制在安全范围内。 |
| PNG 导出比例 | 2x | 兼顾清晰度与文件大小。 |
| 节点文字换行宽度 | 240 px | 只限制标题文字区域；标记、文件按钮与节点边距追加到节点总宽度。 |

表中“布局模式”“主题”“连线样式”“节点形状”“文件收集策略”和“递归扫描子目录”是文档设置；六者以可读 YAML 保存，不能复制进底部压缩 JSON。表中的“默认布局”“默认配色主题”“默认连线样式”“默认节点形状”和“默认文件收集策略”是插件全局设置，为新建文档及旧文件缺失属性提供初值。文档设置变化进入当前视图的撤销栈并触发自动保存；文件收集策略或递归扫描变化还会使当前目录扫描缓存失效。

插件设置和可重建文件索引分开存储。新建导图使用插件全局默认布局、默认主题、默认连线样式、默认节点形状和默认文件收集策略，并使用代码默认的不递归扫描。除非产品需求明确增加树级差异，否则不得把其他全局选项写入 `.mtn.md` Frontmatter 或移入视图菜单。画布左右键行为、节点层级字号与最小尺寸、是否显示源文件入口仍属于固定产品规则，不提供设置项。

## 11. 异常处理与数据安全

### 11.1 原则

- 任何解析错误都不得导致原文件被空数据覆盖。
- 删除节点默认不删除真实文件。
- 批量文件操作执行前展示影响范围，执行后提供结果报告。
- 外部修改与本地未保存修改冲突时优先保留两个副本，再让用户选择。
- 所有自动修复都写入可撤销的会话命令。

### 11.2 典型错误

| 错误 | 行为 |
| --- | --- |
| `schemaVersion` 无效、压缩数据无法解码或结构校验失败 | 尝试从最近备份恢复；失败时以只读模式打开，不使用大纲恢复，也不自动保存。缺少 `documentId` 不属于格式错误。 |
| 大纲缺失或被修改 | 画布不受影响；下一次保存时根据机器数据完整重建大纲。 |
| 文件引用失效 | 保留节点，显示路径快照和修复入口。 |
| 索引损坏 | 隔离旧索引并重建；导图通过 `pathHint` 降级解析。 |
| 保存时文件已被外部修改 | 暂停覆盖，创建恢复副本并打开冲突处理。 |
| 磁盘写入失败 | 保留内存状态和原文件，持续显示“未保存”，允许重试或另存。 |
| 批量移动部分失败 | 不回滚已被外部观察到的成功项，提供逐项结果及可逆项撤销。 |

## 12. 跨平台、可访问性与安全

### 12.1 跨平台

- 所有路径使用 Obsidian Vault 的 `/` 风格相对路径，比较时按平台规则处理大小写。
- 不依赖 Node.js 专属 API 完成核心读写，确保移动端可用。
- 键盘提示根据平台显示 `Ctrl` 或 `Cmd`。
- 系统剪贴板不支持自定义 MIME 或图片时，降级为纯文本或文件导出。
- 桌面端支持左键框选和右键平移；没有独立右键的触摸设备在画布空白区域单指拖动平移，节点长按打开菜单。

### 12.2 可访问性

- 工具栏、菜单和节点操作可由键盘完成。
- 焦点样式与选中样式不能只依赖颜色区分。
- 节点右侧的文件打开和同步状态图标提供可访问名称；错误和保存状态通过非打断式 live region 告知。
- 左下角统计、画布复位、保存、撤销和重做控件提供可访问名称；不可用的历史操作使用原生禁用状态。
- 可见界面字符串集中在 i18n 词条中，根据 Obsidian 语言选择简体中文或英语。
- 主题颜色使用 Obsidian CSS 变量，兼容浅色、深色和高对比主题。
- 缩放只影响画布内容，不影响菜单和弹窗的可读字号。

### 12.3 安全与隐私

- 插件默认不发起网络请求，不上传仓库内容、文件名或 URL。
- URL 只允许安全协议，并使用 Obsidian 提供的外部链接打开方式。
- 节点标题、Markdown 和 SVG/HTML 导出内容必须转义，避免脚本注入。
- Base64 解码、gzip 解压、JSON 解析、图片解码和导出设置体积、节点数量、嵌套深度或像素上限。
- 日志不得记录笔记正文；调试日志默认关闭。
