## 9. 技术架构

### 9.1 模块划分

| 模块 | 职责 |
| --- | --- |
| `MindTreeView` | 注册自定义视图、管理生命周期和状态提示。 |
| `TreeCanvas` | 渲染、布局、选择、缩放、拖拽和可访问性。 |
| `TreeCommandService` | 封装新增、移动、删除、标记等原子命令及撤销/重做。 |
| `DocumentRepository` | 解析、校验、序列化和原子保存 `.mtn.md`。 |
| `MindTreeMigrationFactory` | 按 `schemaVersion` 登记并逐级执行文件结构迁移，向当前领域模型提供唯一兼容入口。 |
| `OutlineRenderer` | 根据树数据单向生成 Markdown 无序列表。 |
| `FileIndexRepository` | 建立、持久化和修复资源索引。 |
| `ResourceService` | 创建、关联、打开、移动文件与处理标题同步。 |
| `TemplateFileService` | 通过窄化 Vault 接口复制任意模板文件、分配独立身份、预留并发路径并回收未关联副本；不解析内部链接。 |
| `DefaultAppOpener` | 只读解析关联文件或安全网页 URL，桌面点击时延迟加载系统打开接口，并统一返回可翻译错误码。 |
| `ClipboardService` | 写入和读取自有 JSON、Markdown、PNG。 |
| `ExportService` | 生成 PNG 和 Markdown 导出结果。 |
| `SettingsService` | 设置读写和默认值。 |

UI 采用命令式 DOM 组件但保持单向数据流。`MindTreeView` 只负责把文档会话映射为不可变界面状态，并把命名操作回调交给下列内部模块：

- `ui/components`：视图外壳、左上菜单栏、顶部工具栏、左下状态栏、状态提示层及分层画布；所有对象具有幂等销毁生命周期。
- `ui/renderers`：节点与连线渲染；只读取渲染状态，不持有视图、插件或仓库。
- `ui/controllers`：框选、平移、缩放、键盘、节点拖动、文件拖入与剪贴板状态机；窗口级监听器必须绑定到视图所属窗口并统一释放。
- `ui/menus` 与 `ui/modals`：右键菜单、单树设置、工具栏菜单和独立对话框对象。
- `ui/settings-pages`：基础设置、思维导图与主题笔记三个页面对象。

组件不得反向导入 `MindTreeView` 或插件主类。界面事件先转换为命名操作，由领域命令产生新文档状态，随后视图重新计算状态并调用组件 `update()`；本阶段仍使用完整布局和重绘，不引入虚拟 DOM。

核心树操作必须与 UI 框架解耦，并通过纯数据单元测试验证。所有文件变更统一经过 `ResourceService`，避免菜单、命令和拖拽各自实现一套规则。

模板流程由 `ResourceIndexService` 向 `TemplateFileService` 提供 `Vault.copy()`、Frontmatter 原子回调、回收站与索引注册接口。模板选择范围是配置目录及子目录内的全部文件；创建路径和新 ID 在异步复制期间预留，索引忽略副本继承旧身份的短暂中间态。普通 Markdown 仅替换嵌套资源 ID，思维树仅替换顶层 `documentId`（不经过导图解析/序列化），其他文件只通过新文件名携带五位 ID。二进制数据不读作文本，内部链接、压缩区与模板变量保持不透明。

视图在模板选择器打开时捕获共享 `AssociationTarget` 的会话令牌与节点 ID，异步复制和提交边界重复验证。服务只拥有未提交副本的回收权限；领域关联成功后显式移交所有权，后续渲染或打开失败不得删除已关联文件。回收使用 Obsidian 回收站并校验文件对象身份，不删除同路径的替换文件；回收失败保留副本并向用户显示路径。普通新建 Markdown 笔记的初始内容流程不经过此服务。

普通笔记、模板、已有文件与网页关联共用 `AssociationTarget` 校验；已有关联不论是否关闭标题同步都不得被替换。入口和弹窗回调检查之外，领域草稿仍需重新检查，避免另一视图的编辑提交改变目标后继续写入。模板未提交副本沿用回收策略，普通笔记已创建而关联失败时保留文件并明确提示路径，已有文件不做删除回滚。右键菜单通过同一纯函数生成资源分组，并用 `ResourceTarget` 在点击时比较会话、节点与稳定文件 ID/URL；路径和标题变化不被误判为资源替换。

系统默认打开与现有 Obsidian 内打开分离。`DefaultAppOpener` 通过注入接口解析规范 `TFile`、取得 `FileSystemAdapter.getFullPath()` 的原生路径，并调用 `shell.openPath()`；HTTP/HTTPS 则调用 `shell.openExternal()`，不支持其他协议，不拼接命令字符串或文件 URL。`openPath()` 的非空返回字符串也按失败处理。菜单与执行入口都检查 `Platform.isDesktopApp`，只有点击后才加载 Electron；系统打开没有文档修改、保存、历史或视口权限。[Electron Shell API](https://www.electronjs.org/docs/latest/api/shell)

文本粘贴和导入通过共享纯函数 `parseTextLine()` 输出有序节点描述，共用 `scanTextLinkSpans()` 的括号、转义与 URL 词法规则；Wiki、Markdown 文件及 HTTP/HTTPS URL 不再相互排斥。单链接保留说明与显示文字，多链接拆成兄弟节点，剩余说明作为第一节点并承担该行后续层级。单行粘贴仅做链接解析，不解析列表/标题结构；列表及多级标题构建器均使用同一行级结果。

文件目标通过临时 `linkTargets` 传递原始路径与失败时恢复的 `fallbackTitle`，先完成运行时森林校验，再由现有 MetadataCache/稳定资源服务关联。视图在身份分配前预先捕获全部目标文件，避免首个附件添加 ID 后导致其他相对路径或别名查找失效；重复源路径复用一次身份结果。异步解析检查源视图会话，成功后只调用一次结构插入命令；缺失文件恢复原始链接文字，身份冲突不猜测。文件标题沿用全局同步设置，开启时直接使用规范文件名，避免保存时闪回；不因导入别名重命名文件。这些解析描述及回退字段在插入前清除，不进入节点压缩 JSON、YAML 或 schema。

内部结构化剪贴板在文本解析之前独立恢复，保留原有标题、标记、子树和资源引用，不执行多链接拆分。节点的 `getNodeResourceControls()` 统一给出打开按钮、文件同步关闭标志及实际宽高，渲染与布局共用，防止 URL 漏图标或错误预留第二个控件位置。

### 9.2 状态流

```text
.mtn.md ──解析/校验──> 领域模型 ──命令──> 新领域模型
   ▲                       │                  │
   │                       ├──> 画布渲染      ├──> 撤销栈
   │                       └──> 资源解析      └──> 延迟保存
   └── 大纲 + 压缩数据区 <──── 序列化 <────────┘
```

领域模型是视图会话中的唯一状态源。组件不得直接修改模型；所有修改都通过命令产生，以保证撤销、保存和测试行为一致。

持久化边界统一由 `DocumentRepository` 负责：文件头写顶层 `schemaVersion` 和六项文档设置，仅在导图已获得跨文件资源身份时写 `documentId`；正文写 Markdown 大纲、AI 忽略提示和 gzip + Base64 压缩 JSON 数据区；`ClipboardService` 的 JSON 是独立的临时交换格式。关联文件状态在文件事件、文档重新加载和序列化之前经过同一校正层：规范路径始终覆盖 `pathHint`，规范文件名只覆盖启用双向标题同步的节点，避免 Obsidian 链接改写载入旧压缩快照后恢复旧标题。

### 9.3 渲染与性能策略

- 布局计算和渲染分离；节点尺寸变化时只使相关分支布局失效。
- 画布导航拆成平移层与内容缩放层：外层使用按设备像素比对齐的 `left/top` 执行屏幕空间平移，不设置长期 `will-change` 或 `translate3d` 合成层；内层优先使用会触发布局和文字重新栅格化的 CSS `zoom`。布局完成后节点锚点取整，节点和连线复用同一坐标。不得在长期合成的世界层上持续使用 `transform: scale()` 拉伸节点文字；仅为不支持 CSS `zoom` 的旧 WebView 在内容层保留缩放回退。
- 根节点、一级节点、二级及更深节点的字号和行高由深度映射函数统一决定；深度二及以后固定返回同一档参数。只有根节点保留 `32px` 最小高度，其他节点按文字行框与内部元素实际高度确定。节点不设固定最小宽度；布局节点同时保存标题区域宽度和完整宽度，后者等于标题区域加尾部元素实际宽度。
- 视觉配色由一级分支决定：根节点使用主题纯色，根节点的 `childIds` 按当前文档顺序依次取得十二个色槽，第十三个分支开始循环；每个一级分支的全部后代节点和连接线继承该色槽。调整一级节点顺序会同步改变色槽；DOM 与 SVG 导出共用相同的分支槽表。所有节点和画布背景均禁止使用渐变。
- 运行时读取当前 Obsidian 字体族、字号、字重、行高、字距、词距、字偶距、字体拉伸及大小写变体，并通过配置相同属性的 Canvas 得到标题实际宽度；无对应 Canvas 能力时只回退缺失属性，无 Canvas 的测试环境才使用确定性估算。测量器输出唯一的明确分行，DOM 不得再对每行执行第二次自动换行。短标题自动收缩，超过全局换行宽度后增加文本行和节点高度。五种布局均以标题区域确定文本锚点，尾部区域固定向屏幕右侧增长；尾部为空时宽度和前置间距均为零，完整矩形仅参与碰撞边界和连线端点。画布与 PNG/SVG 导出共用测量、分行和布局结果。
- 纵向布局以完整子树为边界递归计算：兄弟子树之间始终保留统一最小间距，再将父节点放在子树组的垂直中心。拖拽改变父子关系后必须全量重算，任何深度的节点矩形都不得重叠。
- 均衡布局按一级子树高度贪心分配左右两侧；树形布局递归计算子树宽度；放射布局按叶子权重划分角度，并根据同层节点对角线尺寸动态扩大半径。
- 连线路径与节点排布分离：布局只输出节点矩形，路径层再按布局方向选择边缘锚点，并生成贝塞尔、直线或直角路径；虚线仅由渲染样式控制。
- 大导图使用视口裁剪，仅渲染可见节点及缓冲区。
- 搜索、索引重建、PNG 导出、大纲生成和 JSON 压缩不得长时间阻塞主线程；必要时分片或使用 Worker。
- 打开时优先显示结构，再按资源 ID、规范路径和文件修改时间异步补齐图片节点及失效引用状态。未完成解码时使用紧凑占位尺寸；自然尺寸就绪后保持画布锚点原地重排。
- 图片节点通过 Obsidian 仓库资源地址显示，不持久化 `app://` 地址或对象 URL。加载和导出同时限制单文件字节数与解码像素数，失败或超限时降级为普通关联文件节点。调整尺寸期间只保存运行时临时宽高并实时重排，松开后才以单个领域命令写入节点样式和撤销历史。
- PNG 与内部 SVG 渲染嵌入安全数据 URL；SVG 源图在导出前栅格化，防止把潜在活动内容嵌入生成结果。

性能验收基线（普通近三年桌面设备）：

- 1,000 个纯文本节点的导图在 2 秒内完成首次可交互渲染。
- 500 个可见节点下，普通平移和缩放保持可感知流畅，交互期间不执行同步全库扫描。
- 10,000 个文件的仓库完成首次索引后，单次文件事件使用增量更新。
- 连续编辑不得每次按键写盘。

### 9.4 版本迁移约束

- 当前引入迁移机制前的无版本号文件定义为 v1，也是项目允许读取的最早兼容版本；当前写出格式为 v2。v1→v2 只补充显式版本标记。
- schema v2 以 `.mtn.md` 扩展名、有效 `schemaVersion` 和机器数据区识别导图，`documentId` 是可选链接身份；这一规范调整不提升版本。今后只有影响导图识别、机器数据区定位或核心载荷解码的不兼容结构修改才提升 `schemaVersion`，并在统一 `MindTreeMigrationFactory` 中登记从版本 N 到 N+1 的纯数据迁移。新增可缺省的树设置不提升版本、不进入工厂；视图、领域操作和序列化代码不得各自添加旧格式判断。
- 工厂严格按整数版本逐级迁移；版本低于最早兼容版本、版本高于当前版本、缺少中间迁移或迁移结果校验失败时，只报告错误，不覆盖原文件。
- 迁移在内存副本中完成。成功解析后将视图标记为待保存，由现有原子保存流程把文档、大纲与文件头统一写成当前版本。
- 全局默认布局、主题、连线样式、节点形状与文件收集策略只传给文档设置规范化层，用于缺失属性回填；迁移工厂不读取全局界面设置。
- 任意树设置缺失时统一在运行时采用全局默认值（无全局项时用代码默认值）；不因此标记脏状态或补写 YAML。`document-settings-state` 用 WeakMap 随不可变文档克隆记录原始属性存在性及待写字段，序列化只提交明确修改且未被外部同字段修改覆盖的值。

## 10. 设置设计

设置分为文档设置和插件全局设置。文档设置包含“布局模式”“主题”“连线样式”“节点形状”“文件收集策略”和“递归扫描子目录”，从视图左上角圆形菜单进入，并分别保存为该 `.mtn.md` 的顶层 `layoutMode`、`theme`、`connectionStyle`、`nodeShape`、`collectionMode`、`recursiveScan` YAML 属性。全局“默认布局”“默认配色主题”“默认连线样式”“默认节点形状”和“默认文件收集策略”只在新建导图时复制到文档，也作为旧文件缺失相应属性时的回填值；其余设置仍放在“基础设置 / 思维导图 / 主题笔记”三个全局设置页中。

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 模板文件夹 | 空 | “从模板添加文件”的递归搜索范围，支持全部仓库文件类型。 |
| 新笔记目录 | 当前导图目录 | 普通新笔记及模板副本的保存目录；配置为空时使用当前导图所在目录。 |
| 新笔记默认填充内容 | 空 | 普通新笔记的初始 Markdown 正文；不自动生成一级标题，也不影响模板副本。 |
| 文件收集策略 | 每次询问 | 当前树可选关闭、每次询问、添加到一级末尾或添加到“收集”节点，并写入顶层 `collectionMode`。 |
| 递归扫描子目录 | 关闭 | 避免首次打开产生大量候选。 |
| 扫描忽略规则 | 隐藏目录与插件目录 | 支持路径前缀和扩展名。 |
| 布局模式 | 均衡 | 可选均衡、向右、向左、树形和放射；左上角菜单与命令面板同步切换当前树。 |
| 默认布局 | 均衡 | 只决定新建导图的初始 `layoutMode`，不覆盖已有导图。 |
| 默认文件收集策略 | 每次询问 | 位于全局“思维导图”页，只决定新建导图的初始 `collectionMode`，也用于回填旧文件的缺失属性。 |
| 默认配色主题 | 活力 | 十套内置主题均提供浅色/深色变量；只决定新建导图的初始 `theme`。 |
| 连线样式 | 跟随主题 | 当前树可跟随主题或强制平滑/直角的实线与虚线或直线，写入顶层 `connectionStyle`；所有连线固定为 `1px`，主题继续定义端点、透明度和阴影。 |
| 默认连线样式 | 跟随主题 | 位于全局“思维导图”页，只决定新建导图的初始 `connectionStyle`，也用于回填缺失属性。 |
| 节点形状 | 圆角 | 当前树的形状，可选圆角、方角和无边框；圆角及无边框的可见非叶节点使用 `2px` 圆角，方角使用 `0px`。历史 `capsule`、`sketch` 值按普通无效设置回退为圆角，并写入顶层 `nodeShape`。 |
| 默认节点形状 | 圆角 | 只决定新建导图的初始 `nodeShape`，不覆盖已有导图。 |
| 节点对齐 | 同级节点对齐 | 全局切换为同级共用列/行/半径，或按父节点尺寸就近放置的紧凑布局。 |
| 文件名同步 | 所有新文件关联默认开启 | 可对当前树关闭新关联的默认值，也可在节点菜单逐项取消或恢复。 |
| 非 Markdown 文件标识分隔符 | `@` | 可选 `@` 或 `%`，仅用于新关联文件的 5 位大小写字母数字 ID；历史文件不自动改名。 |
| 关联文件打开位置 | 新标签页 | 可切换为右侧竖向拆分。 |
| Ctrl/Cmd+E 新文件打开位置 | 右侧拆分 | 普通新笔记及模板副本共用；可切换为新标签页、当前标签页或新窗口。 |
| 自动保存延迟 | 500 ms | 限制在安全范围内。 |
| 忽略的文件标签扩展名 | 空 | 全局基础设置；按完整后缀或末级扩展名隐藏扩展名标签（含 Markdown 别名），键不区分大小写，不影响专用徽标。 |
| 文件标签扩展名别名 | 空 | 全局基础设置；以用户原样别名替代后缀显示，支持 `md`、`plugin.md`；完整后缀优先，忽略规则优先。Markdown 未匹配别名时不显示标签，思维树／绘图专用徽标保持不变。 |
| PNG 导出比例 | 2x | 兼顾清晰度与文件大小。 |
| 节点文字换行宽度 | 240 px | 只限制标题文字区域；标记、文件按钮与节点边距追加到节点总宽度。 |

表中“布局模式”“主题”“连线样式”“节点形状”“文件收集策略”和“递归扫描子目录”是文档设置；六者以可读 YAML 保存，不能复制进底部压缩 JSON。表中的“默认布局”“默认配色主题”“默认连线样式”“默认节点形状”和“默认文件收集策略”是插件全局设置，为新建文档及旧文件缺失属性提供初值。文档设置变化进入当前视图的撤销栈并触发自动保存；文件收集策略或递归扫描变化还会使当前目录扫描缓存失效。

插件设置和可重建文件索引分开存储。扩展名标签忽略列表与别名映射属于纯显示插件设置；视图从关联路径实时派生标签并以同一个测量模型提供给布局、DOM 与 PNG/SVG 导出，不写入节点或大纲。新建导图使用插件全局默认布局、默认主题、默认连线样式、默认节点形状和默认文件收集策略，并使用代码默认的不递归扫描。除非产品需求明确增加树级差异，否则不得把其他全局选项写入 `.mtn.md` Frontmatter 或移入视图菜单。画布左右键行为、节点层级字号与最小尺寸、是否显示源文件入口仍属于固定产品规则，不提供设置项。

## 11. 异常处理与数据安全

### 11.1 原则

- 任何解析错误都不得导致原文件被空数据覆盖。
- 删除节点默认不删除真实文件。
- 批量文件操作执行前展示影响范围，执行后提供结果报告。
- 插件级会话注册表按规范路径保证同一文件只有一份内存文档、撤销历史、保存队列与冲突状态；文件重命名只原子更新注册键。一个视图提交命令后，其他视图原地重绘，但不共享选择和视口。
- 同一共享会话只允许一个标题编辑器。另一视图开始编辑或修改结构前先提交已有草稿；正常关闭、切换、主动保存和身份写入均先捕获可见输入框，再销毁 DOM。
- `VersionConflictCoordinator` 仅针对外部 JSON 的实质变化显示双栏选择，干净会话也需要选择。普通属性通过共享会话原地接收并重基历史，不触发节点命令、输入框失焦或视口移动；保存读回时保留写入期间的新编辑。身份分歧显示独立 `DocumentSafetyPanel`；恢复入口经过完整资源身份校验、文件写入队列、YAML 单字段比较写入和读回校验，不允许用普通版本选择绕过。
- 大纲、自动一级标题、普通 Markdown 正文和未知 Frontmatter 是非冲突区；保存必须以最新磁盘文本为底稿，不能用旧基线覆盖它们。
- `PendingConflictStore` 将冻结版本、必要基线、草稿、延后文件改名和提交回执存到插件目录 `pending-conflicts/<本机标识>/`。本机标识来自仓库对应的本地存储；不复用 `data.json`。写入后读回校验，失败保持锁定；关闭和重启恢复未决状态。外部版本只从原文件读取，不累积历史副本。
- 正常保存、身份分配与版本选择共用文件级串行队列。选择捕获点击时的外部指纹，在 `Vault.process()` 再次核对，以最新正文及全部普通 YAML 为底稿；读回一致才提交基线。准备/验证回执识别写入后清理前中断，清理失败可重试。当前选择保留历史，外部选择重建历史基线，不自动拼接节点；普通设置独立采用最新值。旧的属性型未决记录重新分类后可安全恢复，未确认草稿与已确认状态分开暂存，避免恢复身份时意外确认标题或改名文件。
- `VersionComparison` 与 `ReadOnlyTreePreview` 不持有仓库或主视图；两栏复用渲染器，临时折叠、平移和缩放只是展示状态。`MindTreeOpenCoordinator` 按路径合并并发打开任务，复用原标签，避免在冲突预览中反复创建视图。
- 不再创建、校验、扫描、提醒或删除旧 Recovery 文件。已有用户文件保持原样；压缩 JSON 的小写 `recovery.unreachableNodes` 保全机制不属于冲突备份，继续保留。
- `SettingsPersistence` 只串行保存用户设置并接收 Obsidian 外部设置更新；外部更新取消未执行旧快照/重试，不添加自定义跨设备合并。`data.json` 仅含 `settings`。`LocalResourceCache` 使用仓库隔离的本机 localStorage，存储失败降级内存；`ResourceCatalog` 从实际文件身份建立验证快照、保留重复候选并提供分批原子重建，缓存不是归属证明。资源改写按 ID 串行且执行前补验实际身份和唯一性；重复 ID 不自动修复，失败的新建副本仍使用回收站清理。
- 所有自动修复都写入可撤销的会话命令。

### 11.2 典型错误

| 错误 | 行为 |
| --- | --- |
| `schemaVersion` 无效、压缩数据无法解码或结构校验失败 | 以只读错误状态打开，不使用大纲恢复，不自动保存或覆盖。缺少 `documentId` 不属于格式错误。 |
| 大纲缺失或被修改 | 画布不受影响；下一次保存时根据机器数据完整重建大纲。 |
| 文件引用失效 | 保留节点，显示路径快照和修复入口。 |
| 索引损坏 | 丢弃本机缓存并重建；`pathHint` 只有经实际文件 ID 核对后才能解析，禁止猜测同名文件。 |
| 保存时检测到外部机器数据变化 | 暂停所有修改，在原标签显示双栏版本选择；以校验后的独立暂存保留当前版本。 |
| 外部普通 YAML 修改或删除 | 按字段接收最新值；不弹比较、不补回删除字段，更新历史与视图但不提交输入框草稿。 |
| 已有 documentId 被删除或替换 | 显示安全原因及原/现 ID，提供恢复原 ID 与重新检查；重复身份或不可验证状态下不写文件。 |
| 干净会话收到有效但更旧的同步版本 | 同样进入版本选择，不因本地未标记为脏而静默回退。 |
| 写后读回的逻辑快照与预期不一致 | 不显示已保存，不清理未决记录，更新右栏并要求重新选择。 |
| 外部只修改文件名对应标题、大纲、正文或未知 Frontmatter | 不弹冲突；以最新磁盘文本为底稿保存并保留外部内容。 |
| 磁盘写入失败 | 保留内存状态和原文件，持续显示“未保存”，允许重试或另存。 |
| 批量移动部分失败 | 不回滚已被外部观察到的成功项，提供逐项结果及可逆项撤销。 |

## 12. 跨平台、可访问性与安全

### 12.1 跨平台

- 所有路径使用 Obsidian Vault 的 `/` 风格相对路径，比较时按平台规则处理大小写。
- 不依赖 Node.js 专属 API 完成核心读写，确保移动端可用。
- 系统默认打开属于桌面端可选操作，不在移动端显示，也不在模块初始化时导入或调用 Electron；插件继续保持 `isDesktopOnly: false`。仅系统打开时将已解析仓库文件路径转换为原生完整路径，不把它写回资源引用。
- 键盘提示根据平台显示 `Ctrl` 或 `Cmd`。
- 剪贴板读取依次尝试插件结构化数据、事件图片、事件纯文本、系统图片和系统纯文本；图片与文本共存时优先图片。系统剪贴板不支持自定义 MIME 或图片时，降级为纯文本或文件导出。
- 桌面端支持左键框选和右键平移；触摸由独立 `TouchGestureMachine` 与 `TouchGestureController` 按指针类型分流：普通单指滑动平移、长按后拖动节点、长按松手打开菜单、双击原地编辑、双指连续缩放。
- Pointer Events 负责识别，所属窗口捕获阶段的非被动 Touch Events 仅负责画布局部宿主隔离；依据 composedPath、起点和会话令牌识别归属，不更改宿主私有手势或全局设置。指针捕获绑定稳定画布层而非可被重绘替换的节点。
- 节点拖动/图片缩放复用现有控制器，按 pointerId 过滤并区分完成与取消；取消、失焦、隐藏、切换文件及销毁不提交命令。两指加入先撤销结构预览再导航，多指交接重新建立起点。触控平移与缩放只更新视口，按动画帧合并呈现，不写文档。
- `KeyboardAvoidanceController` 使用所属窗口 visualViewport 与真实输入框/光标几何；输入框同步聚焦以保留 iOS 用户激活，监听输入和可视区域变化做最小平移。自动偏移与手动导航分开管理，输入、计时器、指针和 viewport 监听统一幂等释放。

### 12.2 可访问性

- 工具栏、菜单和节点操作可由键盘完成。
- 焦点样式与选中样式不能只依赖颜色区分。
- 节点右侧的文件打开和同步状态图标提供可访问名称；错误和保存状态通过非打断式 live region 告知。
- 左下角统计、画布复位、保存、撤销和重做控件提供可访问名称；不可用的历史操作使用原生禁用状态。
- 可见界面字符串集中在 i18n 词条中，根据 Obsidian 语言选择简体中文或英语。
- 主题颜色使用 Obsidian CSS 变量，兼容浅色、深色和高对比主题。
- 缩放只影响画布内容，不影响菜单和弹窗的可读字号。

### 12.3 安全与隐私

- 插件默认不发起网络请求，不上传仓库内容、文件名或 URL。
- URL 只允许安全协议，并使用 Obsidian 提供的外部链接打开方式。
- 节点标题、Markdown 和 SVG/HTML 导出内容必须转义，避免脚本注入。
- Base64 解码、gzip 解压、JSON 解析、图片解码和导出设置体积、节点数量、嵌套深度或像素上限。
- 日志不得记录笔记正文；调试日志默认关闭。
