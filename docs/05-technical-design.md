## 9. 技术架构

### 9.1 模块划分

| 模块 | 职责 |
| --- | --- |
| `MindTreeView` | 注册自定义视图、管理生命周期和状态提示。 |
| `ExchangeOps` | 复制/剪切/导出/分支引用/Mermaid 命令层：通过 host getter 读取视图活状态，视图只保留同名薄包装；不反向依赖视图或插件主类。 |
| `NodeOps` | 节点结构/删除命令层：新增子/同级/父节点、同级移动、折叠、删除分支或仅节点、删除对话框与回收站流程；全部变更仍走视图的 `commit` 回调，撤销锚点与渲染顺序不变。 |
| `ResourceOps` | 资源关联命令层：创建笔记/TaskNote 辅助、模板副本、关联文件与网页、移动关联文件、标题同步、打开资源；文件写入仍回到视图的统一 `commit`/`applySystemMutation`/`FileAssociationController` 路径，token 与身份校验保持不变。 |
| `SettingsOps` | 设置写入命令层：布局、主题、连线样式、节点形状与文档设置提交；仍走视图的 `commit` 与重扫顺序。`refreshLayoutFromSettings` 因静态测试钉住方法体而保留在视图。 |
| `TreeCanvas` | 渲染、布局、选择、缩放、拖拽和可访问性。 |
| `TreeCommandService` | 封装新增、移动、删除、标记等原子命令及撤销/重做。 |
| `NodeLinkService` | 同一文档内的单向节点引用：校验发起节点、写入/清除目标 id，并在删除节点时清理指向它的引用；不复制任何节点，也不改动 `childIds`。 |
| `MindTreeReferenceService` | 解析笔记内嵌的分支引用：按树身份（`documentId`）与节点 id 定位唯一 `.mtn.md`，只接受解析身份与引用一致的候选；身份重复、路径被另一棵树占用或数据损坏时返回具名失败态而不猜测。按路径缓存解析结果，并随仓库事件按路径失效。 |
| `TreeSnapshotStore` | 保存成功后的本地版本快照：只通过注入的仓库适配器读写库根 `.mind-tree-nature-data/snapshots/`，按 `documentId`（无身份时按规范路径哈希）分目录；逐字节去重、每树 30 份、单份 8 MiB 上限、损坏条目跳过；捕获串行且失败只记录日志，绝不影响保存。 |
| `VersionHistoryModal` | 版本历史弹窗：左侧列出时间、节点数与大小，右侧复用 `ReadOnlyTreePreview` 只读预览；底部恢复按钮只把选中的快照交给注入端口，身份校验、撤销步与 Notice 都由视图/会话负责，弹窗本身不写文件。 |
| `BacklinkIndexService` | 插件级反向引用索引：只读扫描普通 Markdown 笔记的 `mind-tree-ref` 围栏块，按路径缓存 `documentId → 节点 id → [{path, line}]`；按文件事件增量更新，批处理（每 tick 25 个文件）、单文件 2 MiB 与最多 64 个块上限，失败只报告；不写回笔记、不发网络请求。 |
| `backlink-render-model` | 纯函数：把某节点的引用列表投影为“最多 5 个圆点 + `+N` overflow + 胶囊行列表”，供 `NodeRenderer` 绘制；不参与布局，可在无 DOM 环境测试。 |
| `canvas-export` | 纯数据 Canvas 导出：用与 PNG 导出相同的 `layoutTree` 几何生成 JSON Canvas `text` 节点与父子边，固定 48 px 边距、展开折叠分支、按布局选择连接边；文件路径候选 `<标题>.canvas` / `-2` / `-3`，写盘由视图完成。 |
| `DocumentRepository` | 解析、校验、序列化和原子保存 `.mtn.md`。 |
| `MindTreeMigrationFactory` | 按 `schemaVersion` 登记并逐级执行文件结构迁移，向当前领域模型提供唯一兼容入口。 |
| `OutlineRenderer` | 根据树数据单向生成 Markdown 无序列表。 |
| `FileIndexRepository` | 建立、持久化和修复资源索引。 |
| `ResourceService` | 创建、关联、打开、移动文件与处理标题同步。 |
| `TemplateFileService` | 通过窄化 Vault 接口复制任意模板文件、分配独立身份、预留并发路径并回收未关联副本；不解析内部链接。 |
| `DefaultAppOpener` | 只读解析关联文件或安全网页 URL，桌面点击时延迟加载系统打开接口，并统一返回可翻译错误码。 |
| `TaskNotesService` | 可选 TaskNotes 集成：按需读取宿主插件注册表，只接受运行时 API v1 且具备 `tasks.write` 的实例；创建任务笔记并返回真实路径，不缓存 API 实例、不导入 TaskNotes 内部模块。 |
| `ClipboardService` | 写入和读取自有 JSON、Markdown、PNG。 |
| `ExportService` | 生成 PNG 和 Markdown 导出结果。 |
| `SettingsService` | 设置读写和默认值。 |

UI 采用命令式 DOM 组件但保持单向数据流。`MindTreeView` 只负责把文档会话映射为不可变界面状态，并把命名操作回调交给下列内部模块：

- `ui/components`：视图外壳、左上菜单栏、顶部工具栏、左下状态栏、状态提示层及分层画布；所有对象具有幂等销毁生命周期。只读树预览（版本对比双栏与主题悬浮预览）复用同一套布局、文本测量与节点/连线渲染器，不复制渲染逻辑，也不持有文档会话。笔记内嵌的分支引用视图（`mind-tree-ref` 代码块）同样复用该只读预览，只额外提供分支起点、宽度适配与自适应高度、悬浮打开按钮，并通过注入端口取得解析、打开资源与打开思维树的能力；UI 层不反向导入 `MindTreeView` 或插件主类。
- `ui/renderers`：节点与连线渲染；只读取渲染状态，不持有视图、插件或仓库。
- `ui/controllers`：框选、平移、缩放、键盘、节点拖动、文件拖入与剪贴板状态机；窗口级监听器必须绑定到视图所属窗口并统一释放。
- `ui/menus` 与 `ui/modals`：右键菜单、单树设置、工具栏菜单和独立对话框对象。单树设置的主题二级菜单在鼠标悬浮某一行时，通过视图注入的回调显示只读预览；菜单模块只负责探测悬浮行与主题值，不接触预览 DOM 与插件设置。节点右键菜单与工具栏“复制 / 导出”共用同一份菜单描述（`ui/menus/copy-export-menu.ts`）：行序、图标与命令只有一处定义，两个入口不可能漂移；嵌套菜单通过 `MenuItem.setSubmenu()`（未公开 API，`ui/menus/menu-groups.ts` 内做能力探测）渲染，宿主不支持时同一批命令平铺进父菜单。
- `ui/settings-pages`：基础设置、思维导图、主题笔记、管理标记与 AI 五个页面对象。AI 页承载 MCP 服务分区与模型提供商分区；MCP 分区行为判定来自 `services/mcp/settings-page-model.ts`，模型提供商分区的展示规则来自 `services/ai/` 的纯模块与 `ai-providers-view.ts`，模型目录发现来自 `services/ai/model-catalog.ts`；页面自身只做 DOM 组合与命名端口调用。

组件不得反向导入 `MindTreeView` 或插件主类。界面事件先转换为命名操作，由领域命令产生新文档状态，随后视图重新计算状态并调用组件 `update()`；本阶段仍使用完整布局和重绘，不引入虚拟 DOM。

MCP 子系统按“纯协议 / 宿主接线”两半分在 `services/mcp/`：`contracts.ts` 冻结边界接口，`mcp-core.ts`、`json-rpc-core.ts`、`tool-schemas.ts`、`client-config.ts`、`settings-page-model.ts`、`availability.ts`、`connection.ts` 是零 Obsidian 依赖的纯模块，可以被 `node:test` 直接覆盖；`obsidian-tool-host.ts`、`tree-reader.ts`、`tree-locator.ts`、`session-writer.ts`、`http-transport.ts`、`mcp-server.ts` 才允许接触仓库、会话与设置。协议层不引入 `@modelcontextprotocol/sdk`（会带来整棵依赖树并触碰体积上限），只实现传输规范要求的子集：`POST /mcp` 端点、`application/json` 响应、`Mcp-Session-Id` 与 `MCP-Protocol-Version` 头、通知返回 `202`、未提供 SSE 时 `GET` 返回 `405`。

**只有一个服务器，承载全部工具**：`MCP_SERVER_NAME` 固定为 `mind-tree-nature`（同时是 `serverInfo.name` 与复制配置里的 `mcpServers` 键），`tool-schemas.ts` 的工具目录不再按服务器分组、也没有 `server` 字段，`mcp-core` 的 `handleMcpMessage(raw, host)` 始终暴露全部 18 个工具。MCP 客户端的审批策略只能挂在服务器上，所以读与写共用同一条客户端策略；这是产品明确选择合并入站服务的取舍，插件**不对工具调用做权限判断**。`McpServerController` 只有单实例，端口记录保存在 `McpServerRecord`（键 `${manifest.id}:mcp-server`），令牌来自 `settings.mcpToken`；升级时若没有新记录，沿用旧只读记录（`${manifest.id}:mcp-server:read`）的端口与令牌，让已安装的客户端配置继续可用——该配置从此也带写权限。设置模型只保留 `mcpEnabled` 与 `mcpPort`（读取时兼容旧配置端口，都没有时回落默认 `27321`），`mcpWriteEnabled` / `mcpWritePort` 删除。

读取工具经由 `tree-reader.ts` 直接解析文件，**不要求打开视图**；写入工具经由 `session-writer.ts` 复用 `SharedMindTreeSession` 的历史与文件级串行写队列，因此与画布操作共用撤销栈和保存基线，磁盘基线不一致时宁可拒绝也不覆盖。思维树的创建路径被抽到 `services/tree-creation.ts`，界面命令与 MCP 工具共用同一实现。参见 [MCP Streamable HTTP 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)。

模型提供商按“纯配置 / 宿主接线”两半放在 `services/ai/`：`contracts.ts` 冻结设置模型、校验码、页面端口与体积上限；`presets.ts` 保存供应商预设（品牌、分类、默认 API 类型与 Base URL、可用 API 类型、是否需要 API Key/Base URL、是否支持嵌入、OAuth 类型、额外请求项、申请 Key 的链接）；`normalize.ts` 负责 `data.json` 的不可信输入规范化、表单校验、默认地址解析与请求预览；三者零 Obsidian 依赖，可被 `node:test` 直接覆盖。`oauth.ts` 是 OAuth 流程与设备本地凭据管理的编排层（ChatGPT 设备码/浏览器 PKCE、Gemini 浏览器 PKCE、GitHub Copilot 设备码、Claude 手动令牌）；其中 Gemini 的 Google OAuth 客户端不内置，登录时只读取供应商 `additionalSettings.oauthClientId/oauthClientSecret`，缺失即失败关闭且不打开浏览器，`validateProvider` 用 `provider-oauth-client-required` 在表单层拦截。，`connectivity.ts` 是模型行“测试”按钮的最小请求编排（OpenAI-compatible/Responses、Anthropic、Gemini），`model-catalog.ts` 是“拉取模型目录”的只读发现层（OpenAI-compatible/Responses 的 `/models`、Anthropic 的 `/v1/models`、Gemini 的 `/v1beta/models`、OAuth 会话的令牌目录与内置回退列表）；它们都只通过注入端口访问 HTTP、本地存储、外部打开与平台事实，不直接导入 Obsidian。真正接触 Obsidian 的宿主接线只有 `src/main.ts` 的 `aiSettings()`：它把 `requestUrl`、`app.loadLocalStorage/saveLocalStorage`、`Platform.isMobile` 与设置保存接到纯模块上，并让页面只看到一份已解析快照。OAuth 凭据键为 `${manifest.id}:ai-oauth:<providerId>`，只走设备本地存储；供应商（含 API Key）与聊天/嵌入模型随 `settings.aiProviders` / `aiChatModels` / `aiEmbeddingModels` 进入 `data.json`。页面侧 `ui/settings-pages/ai-providers-view.ts` 把一份 `AiSettingsState` 解析为分区文案、供应商卡片、模型行、picker 与表单选项，`ai-providers-section.ts` 与四个 modal（供应商选择、供应商表单、模型表单、模型目录）只把结果写到 DOM 并通过端口执行命名操作。AI 页由 `settings.ts` 的 `availability: "all"` 在所有平台渲染；MCP 分区的不可用性由 `services/mcp/settings-page-model.ts` 的 `supported` 与页面红字 notice 表达，不靠隐藏整个 tab。

核心树操作必须与 UI 框架解耦，并通过纯数据单元测试验证。所有文件变更统一经过 `ResourceService`，避免菜单、命令和拖拽各自实现一套规则。

模板流程由 `ResourceIndexService` 向 `TemplateFileService` 提供 `Vault.copy()`、Frontmatter 原子回调、回收站与索引注册接口。模板选择范围是配置目录及子目录内的全部文件；创建路径和新 ID 在异步复制期间预留，索引忽略副本继承旧身份的短暂中间态。普通 Markdown 仅替换嵌套资源 ID，思维树仅替换顶层 `documentId`（不经过导图解析/序列化），其他文件只通过新文件名携带五位 ID。二进制数据不读作文本，内部链接、压缩区与模板变量保持不透明。

视图在模板选择器打开时捕获共享 `AssociationTarget` 的会话令牌与节点 ID，异步复制和提交边界重复验证。服务只拥有未提交副本的回收权限；领域关联成功后显式移交所有权，后续渲染或打开失败不得删除已关联文件。回收使用 Obsidian 回收站并校验文件对象身份，不删除同路径的替换文件；回收失败保留副本并向用户显示路径。普通新建 Markdown 笔记的初始内容流程不经过此服务。

普通笔记、模板、已有文件与网页关联共用 `AssociationTarget` 校验；已有关联不论是否关闭标题同步都不得被替换。入口和弹窗回调检查之外，领域草稿仍需重新检查，避免另一视图的编辑提交改变目标后继续写入。模板未提交副本沿用回收策略，普通笔记已创建而关联失败时保留文件并明确提示路径，已有文件不做删除回滚。右键菜单通过同一纯函数生成资源分组，并用 `ResourceTarget` 在点击时比较会话、节点与稳定文件 ID/URL；路径和标题变化不被误判为资源替换。

TaskNotes 集成是唯一的可选第三方插件集成：`services/tasknotes.ts` 是零 Obsidian 依赖的纯模块，插件注册表以端口注入（优先 `app.plugins.getPlugin("tasknotes")`，回退 `app.plugins.plugins.tasknotes`），API 每次点击重新解析，因此启用、更新或禁用 TaskNotes 都不需要重载本插件。只接受 `apiVersion === 1` 且 `hasCapability("tasks.write")` 的运行时 API；创建调用只走 `api.tasks.create()`，随后因 TaskNotes 的创建接口不接受目录，再用 `api.tasks.move()` 把任务移入当前思维树目录（要求 `tasks.move` 能力，仓库根目录传空串）。文件名、Frontmatter 与任务字段属于 TaskNotes，本插件不写任务字段，只在移动成功后按最终真实路径写入自己的稳定 `resourceId`、建立节点引用并按偏好打开。缺少 `tasks.move` 时在创建前拒绝；移动失败（例如目标目录已有同名文件）时保留原位置文件、仍建立关联并提示真实路径与原因。插件缺失或版本不兼容时不创建文件、不发起网络请求，也不新增 npm 依赖。

系统默认打开与现有 Obsidian 内打开分离。`DefaultAppOpener` 通过注入接口解析规范 `TFile`、取得 `FileSystemAdapter.getFullPath()` 的原生路径，并调用 `shell.openPath()`；HTTP/HTTPS 则调用 `shell.openExternal()`，不支持其他协议，不拼接命令字符串或文件 URL。`openPath()` 的非空返回字符串也按失败处理。菜单与执行入口都检查 `Platform.isDesktopApp`，只有点击后才加载 Electron；系统打开没有文档修改、保存、历史或视口权限。[Electron Shell API](https://www.electronjs.org/docs/latest/api/shell)

文本粘贴和导入通过共享纯函数 `parseTextLine()` 输出有序节点描述，共用 `scanTextLinkSpans()` 的括号、转义与 URL 词法规则；Wiki、Markdown 文件及 HTTP/HTTPS URL 不再相互排斥。单链接保留说明与显示文字，多链接拆成兄弟节点，剩余说明作为第一节点并承担该行后续层级。单行粘贴仅做链接解析，不解析列表/标题结构；列表及多级标题构建器均使用同一行级结果。

文件目标通过临时 `linkTargets` 传递原始路径与失败时恢复的 `fallbackTitle`，先完成运行时森林校验，再由现有 MetadataCache/稳定资源服务关联。视图在身份分配前预先捕获全部目标文件，避免首个附件添加 ID 后导致其他相对路径或别名查找失效；重复源路径复用一次身份结果。异步解析检查源视图会话，成功后只调用一次结构插入命令；缺失文件恢复原始链接文字，身份冲突不猜测。文件标题沿用全局同步设置，开启时直接使用规范文件名，避免保存时闪回；不因导入别名重命名文件。这些解析描述及回退字段在插入前清除，不进入节点压缩 JSON、YAML 或 schema。

内部结构化剪贴板在文本解析之前独立恢复，保留原有标题、标记、子树和资源引用，不执行多链接拆分。节点的 `getNodeResourceControls()` 统一给出打开按钮、文件同步关闭标志及实际宽高，渲染与布局共用，防止 URL 漏图标或错误预留第二个控件位置。打开按钮的图标由纯函数 `resolveResourceOpenIcon()`（`render/resource-badges.ts`）按资源类型与路径后缀派生：`file-text`（普通笔记）、`git-fork`（其他思维树）、`globe`（URL）、`image`（图片），附件按后缀映射 `music`/`video`/`archive`/`code`/`table`/`file-text`，未知后缀回退 `file`；只读引用、不查仓库、不写文档。失效判定由纯函数 `isResourceInvalid(resource, isFileResolved?)` 完成：URL 用 `isSafeHttpUrl` 判断，文件交给视图注入的解析回调；视图只在 `ResourceIndexService.isVerified()`（`catalog.isFullyVerified()`）后注入解析回调，未完成全库校验时不把“尚未索引”当作失效。派生结果 `invalidResourceNodeIds` 是运行时集合，随每次 reflow 重算，`main.ts` 的删除事件与 `handleResourceMetadataChange` 也会触发重算且仅在集合变化时重排，因此不写盘、不进入文档状态。

### 9.2 状态流

```text
.mtn.md ──解析/校验──> 领域模型 ──命令──> 新领域模型
   ▲                       │                  │
   │                       ├──> 画布渲染      ├──> 撤销栈
   │                       └──> 资源解析      └──> 延迟保存
   └── 大纲 + 压缩数据区 <──── 序列化 <────────┘
```

领域模型是视图会话中的唯一状态源。组件不得直接修改模型；所有修改都通过命令产生，以保证撤销、保存和测试行为一致。

持久化边界统一由 `DocumentRepository` 负责：文件头写顶层 `schemaVersion`、该树已显式拥有的文档设置属性，仅在导图已获得跨文件资源身份时写 `documentId`；正文写 Markdown 大纲、AI 忽略提示和 gzip + Base64 压缩 JSON 数据区；`ClipboardService` 的 JSON 是独立的临时交换格式。关联文件状态在文件事件、文档重新加载和序列化之前经过同一校正层：规范路径始终覆盖 `pathHint`，规范文件名只覆盖启用双向标题同步的节点，避免 Obsidian 链接改写载入旧压缩快照后恢复旧标题。

### 9.3 渲染与性能策略

- 布局计算和渲染分离；节点尺寸变化时只使相关分支布局失效。
- 画布导航拆成平移层与内容缩放层：外层使用按设备像素比对齐的 `left/top` 执行屏幕空间平移，不设置长期 `will-change` 或 `translate3d` 合成层；内层优先使用会触发布局和文字重新栅格化的 CSS `zoom`。布局完成后节点锚点取整，节点和连线复用同一坐标。不得在长期合成的世界层上持续使用 `transform: scale()` 拉伸节点文字；仅为不支持 CSS `zoom` 的旧 WebView 在内容层保留缩放回退。
- 根节点、一级节点、二级及更深节点的字号和行高由深度映射函数统一决定；深度二及以后固定返回同一档参数。只有根节点保留 `32px` 最小高度，其他节点按文字行框与内部元素实际高度确定。节点不设固定最小宽度；布局节点同时保存标题区域宽度和完整宽度，后者等于标题区域加尾部元素实际宽度。
- 视觉配色由一级分支决定：根节点使用主题纯色，根节点的 `childIds` 按当前文档顺序依次取得十二个色槽，第十三个分支开始循环；每个一级分支的全部后代节点和连接线继承该色槽。调整一级节点顺序会同步改变色槽；DOM 与 SVG 导出共用相同的分支槽表。所有节点和画布背景均禁止使用渐变。
- 运行时读取当前 Obsidian 字体族、字号、字重、行高、字距、词距、字偶距、字体拉伸及大小写变体，并通过配置相同属性的 Canvas 得到标题实际宽度；无对应 Canvas 能力时只回退缺失属性，无 Canvas 的测试环境才使用确定性估算。测量器输出唯一的明确分行，DOM 不得再对每行执行第二次自动换行。短标题自动收缩，超过全局换行宽度后增加文本行和节点高度。五种布局均以标题区域确定文本锚点，尾部区域固定向屏幕右侧增长；尾部为空时宽度和前置间距均为零，完整矩形仅参与碰撞边界和连线端点。画布与 PNG/SVG 导出共用测量、分行和布局结果。
- 纵向布局以完整子树为边界递归计算：兄弟子树之间始终保留统一最小间距，再将父节点放在子树组的垂直中心。拖拽改变父子关系后必须全量重算，任何深度的节点矩形都不得重叠。
- 均衡布局按一级子树高度贪心分配左右两侧；树形布局递归计算子树宽度；放射布局按叶子权重划分角度，并根据同层节点对角线尺寸动态扩大半径。
- 连线路径与节点排布分离：布局只输出节点矩形，路径层再按布局方向选择边缘锚点，并生成贝塞尔、直线或直角路径；虚线仅由渲染样式控制。
- 大导图使用视口裁剪，仅渲染可见节点及缓冲区。
- 小地图是浮在画布之上的只读缩略层：投影数学全部是纯函数（`src/render/minimap.ts` 的 `computeMinimapSize`、`visibleWorldRect`、`unionWorldRects`、`createMinimapProjection`、`projectMinimapPoint` / `projectMinimapRect` / `unprojectMinimapPoint` 与 `minimapProjectionForScene`），不读取 DOM、不写文档，可脱离 Obsidian 做纯数据测试。布局变化（或像素尺寸变化）时只重建小地图内容（仅节点缩略几何，不画连线、不使用分支配色）；`render` / `applyViewport` / `resize` 引起的视口变化不重建内容，只更新内容组变换与指示窗口，两者都不触发主画布重排。指针拖动期间冻结世界→缩略图投影，拖动只改画布平移，避免指示框移动引起内容缩放抖动；拖动结束后按新视口重算。小地图不创建长期 GPU 合成层（不使用 `will-change` / `translate3d`），视口仍是会话状态，绝不写盘；关闭设置、解析失败、版本对比等根节点被隐藏或缩略尺寸不可用时整块不渲染。
- 反向引用索引在后台分批进行：每个 tick 最多读取 25 个文件，单文件超过 2 MiB 直接跳过，单个笔记最多解析 64 个引用块；文件未变化时按 `mtime + size` 复用缓存，文件事件只把受影响路径提前处理。索引变更后画布重绘做 200 ms 防抖，连续编辑一篇被引用笔记只重绘一次；重绘期间不重建节点布局。引用圆点/胶囊层绝对定位、不占文档流，气泡不参与布局，节点尺寸、连线与整棵树排布不因引用数量变化；标题编辑与拖拽时该层隐藏。
- 版本快照在保存完成之后异步捕获，并与列出、读取共用同一条串行队列，避免两次并发保存争用序号；捕获不进入保存关键路径，失败不回滚保存。Canvas 导出复用布局与文本测量结果，生成纯 JSON 后一次写盘，不额外扫描仓库。
- 主题悬浮预览与版本对比共用只读渲染管线：固定 4 节点示例树、首次悬浮时惰性创建、每次切换只重算这一棵示例树的布局，不读取当前文档、不写盘、不进入撤销栈；面板固定在 `document.body`，定位与夹紧复用同类弹出层的规则，并设为不接收指针事件。
- 搜索、索引重建、PNG 导出、大纲生成和 JSON 压缩不得长时间阻塞主线程；必要时分片或使用 Worker。
- 打开时优先显示结构，再按资源 ID、规范路径和文件修改时间异步补齐图片节点及失效引用状态。未完成解码时使用紧凑占位尺寸；自然尺寸就绪后保持画布锚点原地重排。
- 图片节点通过 Obsidian 仓库资源地址显示，不持久化 `app://` 地址或对象 URL。加载和导出同时限制单文件字节数与解码像素数，失败或超限时降级为普通关联文件节点。调整尺寸期间只保存运行时临时宽高并实时重排，松开后才以单个领域命令写入节点样式和撤销历史。
- PNG 与内部 SVG 渲染嵌入安全数据 URL；SVG 源图在导出前栅格化，防止把潜在活动内容嵌入生成结果。

性能验收基线（普通近三年桌面设备）：

- 1,000 个纯文本节点的导图在 2 秒内完成首次可交互渲染。
- 500 个可见节点下，普通平移和缩放保持可感知流畅，交互期间不执行同步全库扫描。
- 10,000 个文件的仓库完成首次索引后，单次文件事件使用增量更新。
- 连续编辑不得每次按键写盘。

### 9.4 版本迁移约束

- 当前引入迁移机制前的无版本号文件定义为 v1，也是项目允许读取的最早兼容版本；当前写出格式为 v2。v1→v2 只补充显式版本标记。
- schema v2 以 `.mtn.md` 扩展名、有效 `schemaVersion` 和机器数据区识别导图，`documentId` 是可选链接身份；这一规范调整不提升版本。今后只有影响导图识别、机器数据区定位或核心载荷解码的不兼容结构修改才提升 `schemaVersion`，并在统一 `MindTreeMigrationFactory` 中登记从版本 N 到 N+1 的纯数据迁移。新增可缺省的树设置不提升版本、不进入工厂；视图、领域操作和序列化代码不得各自添加旧格式判断。
- 工厂严格按整数版本逐级迁移；版本低于最早兼容版本、版本高于当前版本、缺少中间迁移或迁移结果校验失败时，只报告错误，不覆盖原文件。
- 迁移在内存副本中完成。成功解析后将视图标记为待保存，由现有原子保存流程把文档、大纲与文件头统一写成当前版本。
- 全局默认布局、主题、连线样式、节点形状与文件收集策略只传给文档设置规范化层，作为未显式设置该项的树的运行时默认值；迁移工厂不读取全局界面设置。
- 任意树设置缺失时统一在运行时采用全局默认值（无全局项时用代码默认值）；新建导图不写入任何设置属性，也不因此标记脏状态或补写 YAML。`document-settings-state` 用 WeakMap 随不可变文档克隆记录原始属性存在性及待写字段，序列化只提交明确修改且未被外部同字段修改覆盖的值；没有归属记录的文档视为不拥有任何属性。

| 嵌入模型 | 空 | 挂在某个供应商下，最多 `128` 项。字段为 `id`、`providerId`、`model`、`name?`、`dimension`；只有预设声明支持嵌入时才提供添加入口。 |
| OAuth 凭据 | 无 | **不属于全局设置**：保存在设备本地存储（键 `${manifest.id}:ai-oauth:<providerId>`），不进入 `data.json`，也不同步到其他设备。ChatGPT、Gemini、GitHub Copilot 的访问/刷新令牌与 Claude 的手动令牌都按此保存；断开连接或删除供应商即清除。 |

表中“布局模式”“主题”“连线样式”“节点形状”“文件收集策略”和“递归扫描子目录”是文档设置；六者以可读 YAML 保存，不能复制进底部压缩 JSON。表中的“默认布局”“默认配色主题”“默认连线样式”“默认节点形状”和“默认文件收集策略”是插件全局设置，为所有尚未显式设置该项的导图（含新建导图）提供运行时默认值。文档设置变化进入当前视图的撤销栈并触发自动保存；文件收集策略或递归扫描变化还会使当前目录扫描缓存失效。

插件设置和可重建文件索引分开存储。MCP 的启用状态、首选端口与**访问令牌**随插件设置进入 `data.json`（令牌必须跨设备固定，否则同步后的客户端配置会在另一台设备失效），而**生效端口与绑定记录留在设备本地存储**：端口是每台机器的事实。`normalizePluginData` 对开关、端口与令牌做不可信输入规范化（开关回落为布尔，端口越界回落为默认值而不是夹紧成另一个可疑端口，格式不合法的令牌清空并在下一次桌面启动重新生成）。模型提供商同样属于插件全局设置，但凭据策略分成两半：`settings.aiProviders`（含**明文 API Key**）、`settings.aiChatModels`、`settings.aiEmbeddingModels` 进入 `data.json`，会随插件数据同步；OAuth 访问/刷新令牌留在设备本地存储，不进入 `data.json`。`normalizeAiSettings` 对三者做不可信输入规范化：未知 preset/API 类型回落到预设默认值、越界数字丢弃、重复 ID 去重、单条损坏的供应商或模型只丢弃自身而不影响其余，并把数量限制在 `64 / 512 / 128`；加载不因一条坏数据失败，也不会把修复结果自动写回。因为 API Key 明文存在 `data.json` 中，界面与文档都必须把它当作敏感数据提醒；日志、状态行与错误消息不得回显 API Key 或 OAuth 令牌。模型目录拉取不是持久化设置：目录结果只用于一次批量创建聊天模型，关闭弹窗即丢弃；远程不可用时使用 `model-catalog.ts` 内置的回退列表，不写入 `data.json`。扩展名标签忽略列表与别名映射属于纯显示插件设置；视图从关联路径实时派生标签并以同一个测量模型提供给布局、DOM 与 PNG/SVG 导出，不写入节点或大纲。自定义标记同样属于纯显示插件设置：`data.json` 的 `settings.customMarkers` 只保存 `{ id, kind, value }`，节点仅保存 `{ type: "emoji" | "tag", value }`，渲染时由 `ResourceBadgePresentation` 用一次渲染快照把值解析为可见项，因此删除一个定义只会让该值停止渲染，节点数据不被改写，重新添加同值即可恢复。新建导图不在 Frontmatter 写入任何设置属性：未显式设置的项在运行时使用插件全局默认布局、默认主题、默认连线样式、默认节点形状和默认文件收集策略，递归扫描使用代码默认的关闭；用户在树菜单主动设置某项后才写入该属性，并从此固定为该树的值。除非产品需求明确增加树级差异，否则不得把其他全局选项写入 `.mtn.md` Frontmatter 或移入视图菜单。画布左右键行为、节点层级字号与最小尺寸、是否显示源文件入口仍属于固定产品规则，不提供设置项。

## 11. 异常处理与数据安全

### 11.1 原则

- 任何解析错误都不得导致原文件被空数据覆盖。
- 删除节点默认不删除真实文件。
- 批量文件操作执行前展示影响范围，执行后提供结果报告。
- 插件级会话注册表按规范路径保证同一文件只有一份内存文档、撤销历史、保存队列与冲突状态；文件重命名只原子更新注册键。一个视图提交命令后，其他视图原地重绘，但不共享选择和视口。
- 同一共享会话只允许一个标题编辑器。另一视图开始编辑或修改结构前先提交已有草稿；正常关闭、切换、主动保存和身份写入均先捕获可见输入框，再销毁 DOM。
- `VersionConflictCoordinator` 仅针对外部 JSON 的实质变化且当前会话存在未保存修改时显示双栏选择；干净会话直接采用磁盘版本（包括同步下来的较旧版本）并重建历史基线，不创建未决记录。普通属性通过共享会话原地接收并重基历史，不触发节点命令、输入框失焦或视口移动；保存读回时保留写入期间的新编辑。身份分歧显示独立 `DocumentSafetyPanel`；恢复入口经过完整资源身份校验、文件写入队列、YAML 单字段比较写入和读回校验，不允许用普通版本选择绕过。
- 大纲、自动一级标题、普通 Markdown 正文和未知 Frontmatter 是非冲突区；保存必须以最新磁盘文本为底稿，不能用旧基线覆盖它们。
- 保存只处理真实的未保存修改：标签页关闭、文件切换、更新器刷新与主动保存都不得为未修改的文档写盘。`Vault.process()` 收到与磁盘完全相同的字节时不会写文件（Obsidian 在回调返回入参时跳过写入），因此不会改变 mtime，也不会让同步客户端把未改动的笔记重新上传。
- `PendingConflictStore` 将冻结版本、必要基线、草稿、延后文件改名和提交回执存到插件目录 `pending-conflicts/<本机标识>/`。本机标识来自仓库对应的本地存储；不复用 `data.json`。写入后读回校验，失败保持锁定；关闭和重启恢复未决状态。外部版本只从原文件读取，不累积历史副本。
- 正常保存、身份分配与版本选择共用文件级串行队列。选择捕获点击时的外部指纹，在 `Vault.process()` 再次核对，以最新正文及全部普通 YAML 为底稿；读回一致才提交基线。准备/验证回执识别写入后清理前中断，清理失败可重试。当前选择保留历史，外部选择重建历史基线，不自动拼接节点；普通设置独立采用最新值。旧的属性型未决记录重新分类后可安全恢复，未确认草稿与已确认状态分开暂存，避免恢复身份时意外确认标题或改名文件。
- `VersionComparison` 与 `ReadOnlyTreePreview` 不持有仓库或主视图；两栏复用渲染器，临时折叠、平移和缩放只是展示状态。`MindTreeOpenCoordinator` 按路径合并并发打开任务，复用原标签，避免在冲突预览中反复创建视图。
- 不再创建、校验、扫描、提醒或删除旧 Recovery 文件。已有用户文件保持原样；压缩 JSON 的小写 `recovery.unreachableNodes` 保全机制不属于冲突备份，继续保留。
- `SettingsPersistence` 只串行保存用户设置并接收 Obsidian 外部设置更新；外部更新取消未执行旧快照/重试，不添加自定义跨设备合并。`data.json` 仅含 `settings`。`LocalResourceCache` 使用仓库隔离的本机 localStorage，存储失败降级内存；`ResourceCatalog` 从实际文件身份建立验证快照、保留重复候选并提供分批原子重建，缓存不是归属证明。资源改写按 ID 串行且执行前补验实际身份和唯一性；重复 ID 不自动修复，失败的新建副本仍使用回收站清理。
- 所有自动修复都写入可撤销的会话命令。
- 版本快照只捕获正常保存管线中**真正写盘成功**的源文本；`identical` 跳过写入、外部版本延迟与冲突选择写盘、MCP 写盘都不产生快照。捕获在保存成功后异步进行，任何 I/O 失败只记录日志并跳过，不回滚、不重试、不延迟已经成功的保存，也不把保存状态改成失败。
- 快照存放在库根 `.mind-tree-nature-data/snapshots/`，与 `.mtn.md`、`.obsidian`、`data.json` 分离；逐字节去重、每树最多 30 份、单份 ≤ 8 MiB、损坏文件忽略。该目录可被同步工具排除，插件不会把快照内容写回笔记。恢复前重新校验快照的 `documentId` / 路径属于当前树，损坏或异树快照只提示；恢复通过 `DocumentSession.replaceDocument()` 产生**一次可撤销记录**，`Ctrl/Cmd + Z` 可回退，恢复本身不绕过会话的删除/冲突锁。
- 反向引用索引只读普通 Markdown 笔记，不写回笔记、`.mtn.md` 或任何插件数据；读取失败、损坏引用块、超大文件与超出块数上限都只跳过该条/该文件并继续，不阻塞画布。索引是内存缓存，插件卸载即丢弃，不构成新的持久化事实。
- 文件可用性只由机器数据区决定：YAML 文件头与可读大纲不参与判定（[03-document-format.md](03-document-format.md) §7.4）。文件头不可解析时设置取运行时默认值、身份保持未定义且**不自动分配**，保存时文件头逐字节保留；只有定位不到数据区、数据区不唯一、无法解码或结构校验失败才判为损坏并失败关闭。
- 读取只采信稳定字节：`readStableSource()` / `confirmUsableSource()`（`src/services/stable-source-read.ts`）要求读取前后文件戳（`path:ctime:mtime:size`）不变，未稳定时按 120 / 400 / 1000 ms 退避重读，最多三次。未稳定的字节既不能作为版本，也不足以判定损坏。
- 路径短暂消失不等于删除：同步客户端和插件自身的重命名会先移除再重建路径，宽限期结束仍不存在才结束文档（父目录消失立即结束，维持既有删除语义）。

### 11.2 典型错误

| 错误 | 行为 |
| --- | --- |
| `schemaVersion` 无效、压缩数据无法解码或结构校验失败 | 稳定重读后仍失败时以只读错误状态打开，不使用大纲恢复，不自动保存或覆盖。缺少 `documentId` 不属于格式错误。 |
| 一次读取读到写了一半或混入旧内容的字节 | 不作为版本、也不判损坏：按文件戳退避重读，状态显示“正在重新读取”；只有稳定且仍不可用才报“文件损坏”。 |
| 打开时解析失败 | 后台对稳定字节重新确认；确认成功即走常规重载路径恢复编辑，确认始终失败才保留错误状态。 |
| 文件头无法解析或缺失 | 按“标记缺失 = v1”解析，设置取运行时默认值，`documentId` 不自动分配；保存只替换大纲区与数据区，文件头逐字节保留（可解析时只补丁插件拥有的键，保留注释与键序）。 |
| 数据区不唯一（同一文件 ≥2 个 `mtn-data-gzip` 块） | 拒绝解析，并拒绝任何改写（不猜测权威数据区）；未闭合的旧围栏按损坏数据区连同装饰行一起替换。 |
| 路径被同步客户端短暂移除 | 宽限期内不上报删除；路径回来即按普通外部修改处理，未做修改的会话照常刷新。 |
| 大纲缺失或被修改 | 画布不受影响；下一次保存时根据机器数据完整重建大纲。 |
| 未修改的导图被关闭、切换或主动保存 | 不请求保存；即使进入保存队列，序列化字节与磁盘一致时也不写文件，文件 mtime 与同步历史不变。 |
| 文件引用失效 | 保留节点，显示路径快照和修复入口。 |
| 索引损坏 | 丢弃本机缓存并重建；`pathHint` 只有经实际文件 ID 核对后才能解析，禁止猜测同名文件。 |
| 保存时检测到外部机器数据变化 | 暂停所有修改，在原标签显示双栏版本选择；以校验后的独立暂存保留当前版本。 |
| 外部普通 YAML 修改或删除 | 按字段接收最新值；不弹比较、不补回删除字段，更新历史与视图但不提交输入框草稿。 |
| 已有 documentId 被删除或替换 | 显示安全原因及原/现 ID，提供恢复原 ID 与重新检查；重复身份或不可验证状态下不写文件。 |
| 干净会话收到有效但更旧的同步版本 | 直接采用磁盘版本：本地没有可丢失的修改，文档、基线、历史与设置状态原地重建，不弹版本选择。 |
| 写后读回的逻辑快照与预期不一致 | 不显示已保存，不清理未决记录，更新右栏并要求重新选择。 |
| 外部只修改文件名对应标题、大纲、正文或未知 Frontmatter | 不弹冲突；以最新磁盘文本为底稿保存并保留外部内容。 |
| 磁盘写入失败 | 保留内存状态和原文件，持续显示“未保存”，允许重试或另存。 |
| 批量移动部分失败 | 不回滚已被外部观察到的成功项，提供逐项结果及可逆项撤销。 |

## 12. 跨平台、可访问性与安全

### 12.1 跨平台

- 核心读写能力不得依赖 Node.js 专属 API；Electron、`node:http` 等桌面能力只能在桌面端点按判断后延迟加载，移动端必须能加载同一份 `main.js`。
- **本机 MCP 服务只在桌面端存在**：`isMcpSupported` 是唯一判定点，`services/mcp/availability.ts` 之后才可能出现 `require("node:http")`；「设置 → AI」页在所有平台渲染，但移动端 MCP 分区显示红字不可用说明、控件禁用，插件也不构造启动器，因此移动端既不会执行该 `require`，也不会监听端口。模型提供商分区与手动令牌在移动端可用；OAuth 连接/取消/断开按钮在移动端禁用。
- 平台门禁优先于设置值：桌面端开启服务后把 `data.json` 同步到移动端，移动端依然不启动服务。
- 所有路径使用 Obsidian Vault 的 `/` 风格相对路径，比较时按平台规则处理大小写。
- 不依赖 Node.js 专属 API 完成核心读写，确保移动端可用。
- 系统默认打开属于桌面端可选操作，不在移动端显示，也不在模块初始化时导入或调用 Electron；插件继续保持 `isDesktopOnly: false`。仅系统打开时将已解析仓库文件路径转换为原生完整路径，不把它写回资源引用。
- 键盘提示根据平台显示 `Ctrl` 或 `Cmd`。
- 剪贴板读取依次尝试插件结构化数据、事件图片、事件纯文本、系统图片和系统纯文本；图片与文本共存时优先图片。系统剪贴板不支持自定义 MIME 或图片时，降级为纯文本或文件导出。
- 桌面端支持左键框选和右键平移；触摸由独立 `TouchGestureMachine` 与 `TouchGestureController` 按指针类型分流：普通单指滑动平移、长按后拖动节点、长按松手打开菜单、双击原地编辑、双指连续缩放。
- Pointer Events 负责识别，所属窗口捕获阶段的非被动 Touch Events 仅负责画布局部宿主隔离；依据 composedPath、起点和会话令牌识别归属，不更改宿主私有手势或全局设置。指针捕获绑定稳定画布层而非可被重绘替换的节点。
- 节点拖动/图片缩放复用现有控制器，按 pointerId 过滤并区分完成与取消；取消、失焦、隐藏、切换文件及销毁不提交命令。两指加入先撤销结构预览再导航，多指交接重新建立起点。触控平移与缩放只更新视口，按动画帧合并呈现，不写文档。
- `KeyboardAvoidanceController` 使用所属窗口 visualViewport 与真实输入框/光标几何；输入框同步聚焦以保留 iOS 用户激活，监听输入和可视区域变化做最小平移。自动偏移与手动导航分开管理，输入、计时器、指针和 viewport 监听统一幂等释放。

### 12.2 可访问性

- 工具栏、菜单和节点操作可由键盘完成。
- 焦点样式与选中样式不能只依赖颜色区分。
- 节点右侧的文件打开和同步状态图标、节点下方的引用圆点组与胶囊按钮提供可访问名称；错误和保存状态通过非打断式 live region 告知。
- 左下角统计、画布复位、保存、版本历史、撤销和重做控件提供可访问名称；不可用的历史操作使用原生禁用状态。
- 可见界面字符串集中在 i18n 词条中，根据 Obsidian 语言选择简体中文或英语。
- 主题颜色使用 Obsidian CSS 变量，兼容浅色、深色和高对比主题。
- 缩放只影响画布内容，不影响菜单和弹窗的可读字号。

### 12.3 安全与隐私

- 插件默认不发起网络请求，不上传仓库内容、文件名或 URL。
- 反向引用索引、版本快照与 Canvas 导出都只在本机读写：索引只读库内 Markdown、不写回笔记，快照写入库根 `.mind-tree-nature-data/`，Canvas 写到源 `.mtn.md` 同目录；三者都不发起网络请求，也不把内容发送给任何服务。
- 网络请求只在用户显式操作时发生，主要包括以下几种情况：
  - **用户主动开启的本机 MCP 服务**（见 9.2）：一条**入站**回环通道，不向任何服务器发送数据；不开启时既不监听端口，也不加载 Node 的 HTTP 模块。该通道只有一个服务器（`mind-tree-nature`），承载全部 18 个工具；插件不对工具调用做权限判断，读与写共用客户端对这条服务器的审批策略——这是合并只读与修改的明确取舍。启用后还必须同时满足四条，缺一不可：① 只绑定 `127.0.0.1`，不监听任何可路由地址；② `Host` 与 `Origin` 头必须落在回环主机集合内，否则拒绝（防 DNS rebinding）；③ 每个请求都必须带 `Authorization: Bearer` 令牌（令牌保存在 `data.json` 的 `mcpToken`，随插件数据同步，使同步后的各设备共用同一客户端配置；拿到令牌即可读写，必须按密码对待）；④ 请求体有固定字节上限，超限在解析前拒绝。
  - **模型连通性测试**：只有点击某个模型行的“测试”按钮后，才向该供应商配置的 Base URL 发送**一次**最小非流式请求。鉴权只使用该供应商配置的 API Key 或设备本地 OAuth 凭据，请求体不含笔记内容、文件名或 URL；不点击、打开设置页或保存配置都不发请求。Azure OpenAI 与 Amazon Bedrock 明确返回“不支持”，不会用误导性的失败结果代替。
  - **拉取模型目录**：只有点击“拉取模型目录”后，才向该供应商的目录端点发一次 GET 请求（OpenAI-compatible/Responses `/models`、Anthropic `/v1/models`、Gemini `/v1beta/models`、OAuth 会话的对应端点），鉴权复用该供应商的 API Key 或设备本地 OAuth 凭据；请求不携带笔记内容、文件名或 URL。远程失败或供应商不支持时使用本机内置回退列表，不发起额外请求。目录结果不持久化，只用于用户勾选后的批量创建。
  - **OAuth 登录**：只有点击“连接”后，才访问对应提供商的授权/令牌端点（ChatGPT、Google、GitHub）；Claude 走手动粘贴令牌，不发起登录请求。设备码或浏览器 PKCE 流程由用户在浏览器里完成；插件只轮询该流程自身的令牌端点，不访问其他服务，也不读取笔记内容。已连接 OAuth 的令牌在读取连接状态时可能自动续期一次（例如 Copilot 的短期令牌过期后后台换取新 token），属于登录会话维护，不发送笔记内容，也不调用模型。AI tab 在移动端也渲染，但 OAuth 的浏览器跳转与本地回调只在桌面端提供，移动端按钮禁用并提示改用手动令牌。
  - **插件更新检查**：按用户在设置中的选择访问 GitHub 发布接口；关闭自动检查后，只有主动点击“检查更新”才请求，且不携带仓库内容、文件名或 URL。
- MCP 通道的日志只记录方法与工具名，绝不记录节点标题或笔记正文；模型提供商相关的日志与错误消息只记录流程状态、HTTP 状态与延迟，绝不记录 API Key、OAuth 令牌、请求头或响应正文。
- API Key、模型配置与 **MCP 访问令牌**以**明文**保存在 `data.json`，OAuth 令牌保存在设备本地存储；用户应把 `data.json` 与其中的全部凭据当作敏感文件。
- URL 只允许安全协议，并使用 Obsidian 提供的外部链接打开方式。
- 节点标题、Markdown 和 SVG/HTML 导出内容必须转义，避免脚本注入。
- Base64 解码、gzip 解压、JSON 解析、图片解码和导出设置体积、节点数量、嵌套深度或像素上限。
- 日志不得记录笔记正文；调试日志默认关闭。
