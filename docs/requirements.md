## 全局交互与格式约束

1. 在画布空白区域按住左键拖拽执行框选；按住右键拖拽移动画布。节点上的右键单击仍打开节点菜单。
2. 节点宽度由标题测量宽度、上下左右各 `2px` 的内边距及尾部元素实际宽度共同决定，不设置固定最小宽度。根、一级、二级及更深节点分别保留 `32/28/24px` 最小高度和对应的三档字号、行高；所有节点无实体边框。
3. 插件不提供“打开思维树源文件”的按钮、菜单项或命令。用户通过导图视图使用 `.mtn.md`，无需访问源文件。
4. `.mtn.md` 用扩展名、有效的顶层 `schemaVersion` 和压缩数据区识别文档；`documentId` 是首次被另一棵树关联时才生成的可选 UUID，不是识别前提。`layoutMode`、`recursiveScan`、`collectionMode`、`theme`、`connectionStyle`、`nodeShape` 各自保存为顶层属性，不使用设置字典，也不在 Frontmatter 保存压缩 JSON。完整机器数据在无序列表大纲之后，以分割线和“这段话之后的内容是压缩json，无需读取和分析。”提示分隔，再写入 gzip + Base64 数据块。当前无版本号格式定义为最早兼容的 v1；只有影响导图识别或核心机器数据解码的结构变化才提升版本并进入统一迁移工厂。任何新增树设置在旧文件中缺失时，直接使用对应全局默认设置补齐并标记待保存，不为普通设置增加迁移版本，也不得在业务代码中散落兼容分支。
5. 文件节点默认让节点名与文件名双向关联；可在节点右键菜单第一项取消名称关联。节点内部不显示左侧类型图标，文件节点最右侧显示 `fa-share-square-o` 打开按钮，打开位置由设置决定。
6. `Ctrl/Cmd+E` 只为未关联节点创建 Markdown 笔记；已关联节点显示提示。普通新笔记正文使用全局“新笔记默认填充内容”，不根据节点名自动生成一级标题，模板副本不叠加该内容；创建后可按全局设置在右侧拆分、新标签页、当前标签页或新窗口打开。
7. 所有用户界面文案通过 i18n 提供简体中文和英语两套资源，并跟随 Obsidian 界面语言。
8. 每个导图视图左上角提供竖向圆角菜单栏：树设置按钮只放置布局、主题、连线样式、节点形状、文件收集策略与“扫描子目录”，圆形问号按钮显示完整快捷键表。全局布局、主题、连线样式、节点形状和文件收集策略只作为新建导图以及旧文件缺失属性回填所需的默认值；主题笔记、删除/导出、扫描忽略规则，以及其余外观和节点对齐偏好保留在插件全局设置页。文件收集策略可选关闭、每次询问、添加到一级末尾、添加到收集节点。十套主题按根节点一级分支的当前顺序循环使用十二色，前十二个分支颜色不重复且每个分支的后代继承该分支颜色；主题分别定义连线路径、虚实、端点、透明度和阴影，所有连线的实际描边宽度统一为 `1px`。
9. 左下角状态栏显示主题数、去重后的 Markdown 笔记数和树深度，依次提供根节点 100% 复位、红绿保存状态和手动扫描当前文件夹新增文件的按钮，以及位于圆角矩形外部的独立撤销、重做按钮；顶部工具栏不重复显示撤销、重做。
10. 节点右键菜单在删除板块下方提供“将笔记移动到”，可搜索仓库文件夹、快速填入当前导图文件夹，并选择只移动当前笔记或移动当前分支的全部笔记。
11. 新建和打开导图的首个可见画面始终以 100% 缩放将根节点精确居中并选中，不显示通用“思维树视图”切换通知；方向键支持兄弟与父子节点导航，新建节点的编辑焦点继续使用普通选中的虚线外框，不放大节点。
12. 多选节点后，按住任意已选节点拖拽会移动全部选中分支。选中集合同时包含祖先与后代时只移动最上层分支并保留内部连接；来自不同子树且未连同父节点选中的分支，在目标落点统一成为同级兄弟节点。拖拽预览仍只显示鼠标按住的一个节点。
13. 节点标题保持左对齐；没有标记、资源徽标或资源按钮的纯文本节点不得为隐藏控件预留尾部空间，标题内容块应在节点内整体居中。
14. 顶部文本导入窗口通过用户手动选择的“列表 / 缩进文本”或“多级标题”规则建立节点层级，并自动解析其中的 Wiki/Markdown 文件链接和 HTTP/HTTPS URL；外部直接粘贴只处理单行文字和整行 URL，多行文本转入预填导入窗口，插件内部结构化分支粘贴保持不变。活动导图必须能在首次粘贴事件缺少纯文本时通过系统剪贴板完成同一次操作，且不得拦截可见输入控件的原生粘贴。新关联的非 Markdown 文件使用 5 位大小写字母数字 ID，并按“主题笔记 → 笔记关联”中的 `@`/`%` 分隔符设置写入文件名；设置只影响新文件，历史 `~mtn-<10 位 ID>` 继续解析且不自动改名。

具体交互见[第 6 节](02-interface-interactions.md)，文件结构见[第 7 节](03-document-format.md)，最终交付判断见[第 14 节](06-quality-roadmap.md)。
