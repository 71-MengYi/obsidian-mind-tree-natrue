# 04 资源索引与引用

> 定义稳定资源 ID、本机索引、引用解析顺序与文件事件。
> [返回文档导航](requirements.md)

## 8. 文件索引与引用解析

### 8.1 索引职责与持久化边界

- `data.json` 仅保存 `{ settings: ... }`。节点、关联及单树设置仍在各自 `.mtn.md` 中；未决导图版本暂存保持独立。
- 资源索引通过 Obsidian 仓库隔离的 `App.loadLocalStorage/saveLocalStorage` 保存到本机专用键 `mind-tree-nature:resource-index:v1`，不在仓库写入第二份可同步索引 JSON。
- 缓存仅保存 `resourceId`、路径、文件类别和可选 Excalidraw 子类型；同一 ID 的所有候选路径均保留，不指定“历史所有者”。缓存只用作扫描提示，任何缓存条目必须经过实际文件校验才能参与解析。
- 内存另有文件对象、修改时间、大小及事件序号，用于拒绝读取期间发生变化的结果；这些观测信息不进入导图或用户设置。
- 缓存缺失、损坏、版本不符或容量不足时使用内存索引并重建，不影响用户设置、不自动修改文件，不回退到 `data.json` 保存索引。

### 8.2 稳定 ID 的文件内表示

资源的稳定 ID 必须随文件同步，插件私有索引只保存可重建的映射：

- 普通 Markdown 文件在首次被导图关联时，将完整 UUID 写入 Frontmatter。该属性使用嵌套 YAML，不使用 JSON 字符串，也不写格式版本：

  ```yaml
  mind-tree-nature:
    resourceId: 018f1f15-3be0-7b0b-8fc8-688a48a0f542
  ```

- `.mtn.md` 不重复增加 `resourceId`。新建树默认没有资源 ID；首次被另一棵树关联时才生成随机 UUID，并写入 Frontmatter 顶层 `documentId`。
- 图像、PDF 等非 Markdown 文件不能写 Frontmatter，因此在首次被导图关联时重命名为 `<原名称><分隔符><短ID>.<扩展名>`。短 ID 固定为 5 位大小写字母或数字；例如默认设置下生成 `architecture@Ab3x9.png`。
- “主题笔记 → 笔记关联”中的“非 Markdown 文件标识分隔符”可选 `@` 或 `%`，默认 `@`。该选项只影响尚未获得稳定 ID 的新关联文件；修改设置不会批量重命名历史文件。
- Markdown 文件无论首次关联还是随节点名同步重命名，文件名都不得追加 ID 编码；只有非 Markdown 文件才追加或保留短 ID 后缀。生成新 ID 时必须检查当前索引唯一性，不能只依赖随机概率。
- 历史 `~mtn-<10 位 Crockford ID>` 后缀继续参与解析、索引重建、标题隐藏和重命名保留，但插件不再生成该格式，也不会自动迁移历史文件名。用户可以手动改成当前格式，不修改也不影响关联解析。
- 文件索引可以记录尚未关联文件的临时路径条目，但不得仅为建立索引而批量修改所有文件。稳定 ID 在资源首次被导图管理时才写入。
- 写入 Markdown Frontmatter 或为非 Markdown 文件追加 ID 后缀必须通过 Obsidian API 完成，并触发其链接更新机制；失败时中止关联，不留下只存在于节点中的 ID。
- UI、节点标题和默认导出名称应隐藏当前 `@/% + 5 位 ID` 与历史 `~mtn-` 后缀；插件同步重命名时必须原样保留文件已有的分隔形式和 ID。

复制文件可能复制已有 ID。多个现存文件共享 ID 时，只列出冲突路径，不再根据历史索引判断原件，不自动重分配任一既有文件的身份。拒绝新的关联及重命名、移动、删除文件；已有引用只有在路径与实际 ID 同时匹配时允许只读打开。正常首次关联无 ID 文件、明确从模板或外部导入创建副本时，仍按原规则生成独立身份。


### 8.3 引用解析顺序

1. 当前 `pathHint` 文件存在，且从文件实际身份校验出的 ID 相同，优先使用该精确路径；重复 ID 也不能让已知路径被另一副本替代。
2. 路径失效时，仅在全部候选已验证、该 ID 只有一个现存候选时回退到新路径。未知或读取失败的文件不得被当作已排除的重复候选。
3. 缓存缺失或过期时，Markdown 直接读取 Frontmatter（不解压思维树 JSON）；非 Markdown 读取文件名中的当前或历史 ID，不读取二进制内容。
4. 无法可靠定位时保留节点及原引用，等待文件/元数据事件或用户重建。禁止按同名、相似路径、旧缓存或轻量指纹猜测目标。
5. 打开和系统默认打开异步补验实际身份；重命名、移动、删除还必须确认 ID 唯一。异步完成后重新检查视图会话与关联目标。

### 8.4 文件事件

- **文件修改**：使旧观测失效，再读取当前身份。文件创建、前台关联、扫描及后台通知共享同一路径的在途校验，避免多个读任务互相覆盖。
- **元数据通知**：仍读取实际文件补验，但不把一次元数据解析完成误当作另一次文件修改；已有读取时合并为一次后续补验。读取期间的真实变化最多进行三轮校验，只重读，不重做创建、ID 分配或改名。持续变化、身份不符和读取失败仍停止关联。
- **观测时序**：读结果带运行时顺序，旧扫描候选不能覆盖更新的校验结果；即使同步内容早于文件时间戳或事件到达，也须使过期唯一性检查失效。尚未完成的元数据补验不能被当作已验证索引。
- **重命名/移动**：校验新路径实际 ID 后，复用资源校正流程更新已打开导图的路径及双向同步标题。每个引用独立核对路径；不得仅凭相同 ID 把多个不同文件的引用改为一个候选。
- **删除/重新创建**：旧路径对象与观测失效。路径被其他 ID 的文件占用时不能继承旧身份；节点不会随文件消失自动删除。
- **仓库切换/缓存丢失**：重新扫描；文件本身携带的身份是权威，不依赖另一设备的缓存。

### 8.5 手动重建

基础设置增加“资源索引 → 重建索引”。扫描分批执行、显示进度并合并重复请求；扫描期间出现的新增、修改、删除和重命名会被重新核对，稳定后一次性替换索引。

完成后显示已索引文件数、重复 ID 组及读取失败路径。整体失败保留此前仍有效的运行时索引；局部失败不能继承未经验证的旧映射。仅刷新资源显示，不改变选择、缩放、画布位置、撤销历史或导图保存状态。该操作不分配 ID、不重命名文件、不修改正文或导图。

### 8.6 用户设置同步与升级

设置通过 `loadData/saveData` 与 `onExternalSettingsChange` 配合 Obsidian 原生同步；不提供插件自定义设置合并、冲突弹窗或设备锁。外部更新使尚未执行的旧保存/重试失效；读取失败保留内存，禁止用默认设置覆盖损坏文件。资源扫描、缓存更新和插件卸载不保存设置。

首次升级以原子回调收到的最新文本移除旧 `resourceIndex`，保留设置原值；旧索引不迁为可信本机数据。旧版本再次同步来的索引只忽略，不产生清理回写循环；下次用户保存设置仅输出 `settings`。请同步升级所有设备，避免旧版继续写入旧索引。

同一设置的跨设备并发修改仍由 Obsidian 原生规则裁决，不能承诺双方值均被保留；本机串行队列不是跨设备锁。

### 8.7 批量关联与创建结果

目录收集以整批操作共享开头和结尾的索引检查，中间只校验各目标及发生变化的文件。已验证且未变化的条目直接复用，不为每个目标反复全库扫描，也不对缓存条目分批定时等待。最终必须确认身份唯一且目标文件仍有效，失败项不进入节点关联；无法证明整体索引有效时不得猜测唯一性。

`Ctrl/Cmd+E` 与右键添加笔记对同一节点合并在途创建请求。文件创建成功后即保留其对象与路径，后续身份校验或目标校验失败时明确提示“已创建但未关联”。普通新笔记不自动删除，自动重读也不创建第二个文件。模板副本仍沿用原有回收规则。
