# 04 资源索引与引用

> 定义稳定资源 ID、文件索引、引用解析顺序与文件事件。  
> [返回文档导航](requirements.md)

## 8. 文件索引与引用解析

### 8.1 索引职责

文件索引保存仓库内文件的：

- 稳定 `resourceId`。
- 规范化路径、文件名、扩展名和类型。
- 创建、修改时间与轻量指纹。
- 最近一次确认存在的时间。

索引不保存文件正文，也不取代 Obsidian `MetadataCache`。首个版本使用插件私有的索引文件持久化，并通过仓库的 `create`、`delete`、`rename`、`modify` 事件增量更新；检测到事件遗漏或索引结构变化时，使用文件自身携带的 ID 执行全量重建。

### 8.2 稳定 ID 的文件内表示

资源的稳定 ID 必须随文件同步，插件私有索引只保存可重建的映射：

- 普通 Markdown 文件在首次被导图关联时，将完整 UUID 写入 Frontmatter。该属性使用嵌套 YAML，不使用 JSON 字符串，也不写格式版本：

  ```yaml
  mind-tree-nature:
    resourceId: 018f1f15-3be0-7b0b-8fc8-688a48a0f542
  ```

- `.mtn.md` 不重复增加 `resourceId`。新建树默认没有资源 ID；首次被另一棵树关联时才生成随机 UUID，并写入 Frontmatter 顶层 `documentId`。
- 图像、PDF 等非 Markdown 文件不能写 Frontmatter，因此在首次被导图关联时重命名为 `<原名称><分隔符><短ID>.<扩展名>`。短 ID 固定为 5 位大小写字母或数字；例如默认设置下生成 `architecture@Ab3x9.png`。
- “主题笔记 → 笔记关联”中的“非 Markdown 文件标识分隔符”可选 `@` 或 `%`，默认 `@`。该选项只影响尚未获得稳定 ID 的新关联文件；修改设置不会批量重命名历史文件。
- Markdown 文件无论首次关联还是随节点名同步重命名，文件名都不得追加 ID 编码；只有非 Markdown 文件才追加或保留短 ID 后缀。生成新 ID 时必须检查当前索引唯一性，不能只依赖随机概率。
- 历史 `~mtn-<10 位 Crockford ID>` 后缀继续参与解析、索引重建、标题隐藏和重命名保留，但插件不再生成该格式，也不会自动迁移历史文件名。用户可以手动改成当前格式，不修改也不影响关联解析。
- 文件索引可以记录尚未关联文件的临时路径条目，但不得仅为建立索引而批量修改所有文件。稳定 ID 在资源首次被导图管理时才写入。
- 写入 Markdown Frontmatter 或为非 Markdown 文件追加 ID 后缀必须通过 Obsidian API 完成，并触发其链接更新机制；失败时中止关联，不留下只存在于节点中的 ID。
- UI、节点标题和默认导出名称应隐藏当前 `@/% + 5 位 ID` 与历史 `~mtn-` 后缀；插件同步重命名时必须原样保留文件已有的分隔形式和 ID。

复制文件可能复制已有 ID。索引已有历史记录时，历史所有者路径保留 ID，新出现的副本在首次关联前生成新 UUID；扫描、修改和拖拽关联都不得用重复项覆盖规范所有者。若现存路径中无法判断原件，则拒绝关联、列出全部冲突路径，并且不修改任一文件或创建错误节点。

### 8.3 引用解析顺序

节点引用本地文件时保存 `resourceId + pathHint`。解析顺序为：

1. 若规范化 `pathHint` 指向现存文件且该文件的稳定 ID 匹配，优先使用该精确路径；这可防止重复 ID 把已知链接重定向到另一份副本。
2. 否则通过当前设备索引中的 `resourceId` 查找；重复 ID 只有在规范所有者有历史依据时才允许解析到该所有者。
3. 索引缺失或过期时，从 Markdown Frontmatter、`.mtn.md` 的可选 `documentId` 或非 Markdown 文件名后缀重建 ID 映射，且扫描不得让后遇到的重复项覆盖既有所有者。
4. 使用 Obsidian 链接解析规则按相对路径和文件名查找。
5. 使用轻量指纹搜索移动后的候选文件。
6. 仍无法唯一确定时标记为失效，并让用户从候选列表手动修复。

稳定 ID 是首选身份，`pathHint` 是跨设备首次解析和索引损坏后的恢复线索。索引是可重建缓存，不能成为导图可读性的单点故障。

### 8.4 文件事件

- **重命名/移动**：更新索引，并在文件事件、导图重新加载和保存前复用同一资源校正流程。该流程始终修复当前已打开导图中的 `pathHint`；双向标题同步节点还从规范文件名恢复节点标题，已关闭同步的节点保留自定义标题。若 Markdown 重命名时 MetadataCache 尚未返回 Frontmatter ID，索引暂时沿用旧路径对应的稳定身份，不得制造无法解析窗口。非 Markdown 文件改名时保留已有的当前或历史 ID 后缀。后台更新未打开导图可延迟执行，但要加入待处理队列。
- **删除**：保留节点和路径快照，标记引用失效；不自动删除节点。
- **重新创建**：若 ID 或路径能唯一匹配，恢复引用；否则等待用户确认。
- **仓库切换或索引丢失**：重建索引，期间允许以路径降级打开导图。
